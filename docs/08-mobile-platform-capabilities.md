# Android / iOS 浏览器与 PWA 能力报告

本报告区分三件事：浏览器是否暴露 API、Tokimeki 是否已经接入该 API、操作系统是否允许它在后台可靠运行。三者不能互相替代。

设置中的 `数据与隐私 → 移动端与 PWA 能力` 会纯本地读取当前环境，不申请权限、不注册 Service Worker、不调用 Provider。

## 当前代码状态

- 已有 PWA manifest、portrait standalone 外壳、PNG/maskable/Apple Touch 图标与安全区布局。
- 已有 `visibilitychange` / `pagehide` 落盘；未完成的面对面回复回到前台后标记为中断并允许手动重试，不重复应用 ops。
- 已有 Media Session 元数据与播放、暂停、上一首、下一首回退。
- 已有 IndexedDB 容量估算和由用户显式触发的持久化存储申请。
- 当前没有注册 Service Worker，因此不提供离线应用壳、Web Push 或后台同步。
- 当前没有通知权限申请入口，也不会在加载页面时自动弹出权限提示。

## 不纳入纯前端版本的承诺

- 应用关闭后由服务器推送角色消息。
- 系统杀死浏览器/PWA 后继续生成回复。
- 每日固定时间可靠唤醒并执行世界更新。
- 用静音音频、Wake Lock 或 Media Session 绕过系统后台策略。
- 把 Service Worker 当作常驻进程。

以上能力若需要远程推送服务、账号系统或常驻后端，会与当前纯前端架构冲突；若未来采用移动端原生壳，必须按平台权限另行设计与真机验收。

## 用户真机检查表

代码侧不能替代以下验证。每条结果应记录设备、系统版本、浏览器版本和“浏览器标签页 / 主屏幕 PWA”形态：

1. 添加到主屏幕后图标、启动页、纵向布局和安全区是否正常。
2. 输入未发送文字后切后台 30 秒再返回，草稿是否保留。
3. 生成回复期间切后台再返回，是否显示中断与手动重试，并且没有重复 ops。
4. 音乐播放期间锁屏，元数据和播放控制是否出现；暂停、上一首、下一首是否有效。
5. 浏览器或系统清理空间前后，IndexedDB 是否仍在；全局备份能否恢复。
6. 后续通知切片完成后，权限拒绝、允许和系统关闭通知三种状态是否都能正确降级。

测试失败不应通过自动重复 API 请求补偿。可靠的最低行为始终是：已输入和已生成内容落盘、状态可解释、用户显式重试、ops 不重复执行。
