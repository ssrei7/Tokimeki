# 决策记录

本文件记录已定方案**及被否决方案的否决理由**。提出这里已否决的方案前，请先读完对应条目。

---

## D1 纯前端 + 用户自带 API
**决定**：静态站点，用户自行配置 API endpoint/key，项目不提供推理服务。
**理由**：省掉后端、账号、计费、服务器成本与大部分内容合规责任，使单人可完成。
**否决**：自建后端代理 —— 引入成本与运维，且需承担 key 托管责任。
**已知代价**：浏览器直连部分厂商有 CORS 限制。对策：内置适配器 + 通用适配器（用户自填请求模板与 JSONPath）+ 连接测试与可读错误诊断 + 后期 Tauri 桌面版。

## D2 天数制，游戏时间与现实时间脱钩
**决定**：以"天"为剧情推进单位，每天结算。
**理由**：给记忆压缩提供天然切点（日记）；存档快照单位直观且数量可控；事件排程可视化为日历，可埋伏笔。
**否决**：真实时间感知 —— 玩家离线世界仍在走，导致回归即错过内容、状态难解释。可作为后期可选开关，不作核心。
**否决**：按楼层/消息数推进（ST 模式）—— 摘要切点常落在场景中间，加剧性格漂移。

## D3 时段制 + 成本表
**决定**：一天分若干时段（世界时钟单位），行动按成本表消耗时段。预设悠闲 6 / 标准 4 / 紧凑 3。
**理由**："每天能做几件事"是时段数 ÷ 平均成本的派生结果，用户调任一侧即可，无需特殊逻辑。移动消耗时段使地理产生重量，"住得近"成为数学而非文案。
**约束**：成本表随时可改；时段数在建世界时确定并默认锁定（NPC 日程按时段 id 映射，中途变更会造成日程空洞与日历错位）。变更需走带警告的重映射向导。
**收费项**：跨区域移动 1 / 打工一班 2 / 探索未知地点 1 / 休息 1 / 剧情事件由事件自行声明。
**免费项**：同区域内移动、偶遇、对话、查看类操作。
**否决**：交互收费 —— 会让玩家算计、不敢乱逛，直接杀死探索欲，与项目立意冲突。
**附加**：提供"无限时段沙盒"开关，服务纯聊天取向用户。体力等第二资源推迟至阶段 8，先在成本表预留 `energyCost` 列。

## D4 图结构地图 + 热点图
**决定**：地点为图节点，边为路径+通行时间，SVG 渲染；另支持用户上传地图图片并钉坐标。
**理由**：无需美术资源与碰撞系统，AI 可直接输出 JSON 图；热点模式把美化权交给用户，利于内容分享。
**否决**：瓦片地图 + 可行走小人 —— 需大量美术、碰撞、精灵动画，与 AI 生成机制不契合，会拖垮项目。

## D5 确定性内核 + ops
**决定**：AI 回复末尾输出受限 op 数组，代码校验后执行。
**理由**：唯一能长期防住状态漂移的结构。
**要求**：op 为白名单注册表；宽松解析 + 修复 + 单次重试；解析失败绝不丢正文，标记"本回合无状态变更"并提供手动补录/重试；提供调试面板展示拼装后的 prompt、原始回复、ops diff；可选用小模型做二段式结构化抽取。

## D6 惰性求值，不做逐 tick 模拟
**决定**：时间推进只跑代码（日程移动、数值衰减、事件出队）；AI 仅在玩家实际观测时补写叙述。
**否决**：每 tick 为每个 NPC 调用 API —— 20 NPC × 4 时段 = 80 次/游戏日，成本不可接受。
**否决**：真实运行 NPC 之间的幕后对话 —— 改为玩家打听时生成"传闻/流言"总结，体感几乎无差，成本低两个数量级。

## D7 NPC 三层分级 + 晨间世界更新合并调用
**决定**：正式角色（完整卡+独立记忆+独立日程，互动时单独调用）／半正式 NPC（名字+既成事实+轻记忆，打包进每日一次调用）／背景 NPC（seed+模版，现场生成不落库）。
**决定**：每游戏日一次「晨间世界更新」调用，合并产出报纸/传闻、半正式 NPC 动向、天气、世界微变。
**要求**：报纸含四类条目 —— 硬线索（指向具体地点+时段）／软氛围／角色相关／伪装成广告的系统入口（招聘、租房、店铺转让）。把昨日日记喂进 prompt 以产生回声。未选中的钩子回池，数日后重现或过期。形式随世界观换皮（报纸/委托板/终端推送/酒馆流言）。
**衍生**：随机 NPC 可"转正"，由 AI 扩写为完整角色卡并落库。

## D8 多轴关系 + 阶段标签，数值默认隐藏
**决定**：关系拆为可独立移动的多条轴（亲密／信任／张力／熟悉度，可由用户扩展），由轴与 flags 推导出阶段标签（陌生人／面熟／熟人／朋友／知己／暗流／恋人／决裂）。进 prompt 的是标签，不是数字。
**理由**：单标量表达不了"贴得很近但始终防着你"这类状态；隐藏数值可避免玩家把体验降格为刷数值；角色卡可合法配置"初登场即高亲密低信任"。
**否决**：取消机器可读关系状态、仅靠性格驱动 —— 长线必然漂移，且同阶段每次相遇读起来雷同。
**必须补充**：当前情绪（一个词 + 数日衰减）与当下处境（正在做什么、忙不忙）。这两项才是"活着"的来源。
**免费红利**：记录上次见面日期，prompt 写入"已 N 天未见"，无需新增数值。
**要求**：关系不单调上升；引入"心结"flag，不处理则持续存在。结算页用散文描述变化，设置内提供显示数值的开关。

## D9 话题树：一次生成 + 双解锁机制
**决定**：进入场景时一次调用生成 4–8 个话题及其简短回应文本，内联存储；后续点击为纯本地渲染。同时支持 `require`（话题始终存在，条件不满足则隐藏或显示为 `???`）与 `unlock_topic`（聊完 A 动态出现 B）。AI 生成默认用 `require`。
**理由**：唯一能让"每个话题都能选一遍"在成本上成立的做法，同时消除延迟。
**要求**：话题带 `terminal` 字段区分纯聊天话题与推进型选项；已聊过的话题不置灰，改为返回缓存的敷衍变体；日常话题按天刷新，剧情话题永久保留；自由输入永远与话题按钮并存，且允许 AI 反向 `unlock_topic`。

## D10 单张立绘，无表情系统
**决定**：当前产品界面只为角色维护一张可选立绘，新上传会替换旧立绘。存档继续保留 `portraits[]` 与 `activePortraitId` 以兼容旧存档和导入内容，但内置编辑器最多写入一项。另有独立头像用于地图图钉、联系人和消息。
**理由**：表情系统需要资产管线、表情名匹配与 AI 别名回退，成本远高于收益。
**否决**：多表情 + AI 内联表情标记 —— 推迟，且当前不预留复杂结构。
**要求**：立绘全程可选；面对面场景缺少立绘时保留空的立绘区域，不用头像或首字替代。头像缺失时才使用角色配色与姓名首字占位。缺少任何视觉资产都不得报错；导入时提供降采样（限高、转 webp）；导出包打包实际引用的本地资产。

## D11 日结算 + 日记即记忆压缩
**决定**：每日结算生成日记，原始对话可丢弃。长期上下文 = 角色卡 + 关系摘要 + 最近 7 天日记 + 重要事件里程碑；更早的压为周摘要、章节摘要。
**理由**：一鱼两吃 —— 情绪价值与上下文控制同时解决。
**要求**：地点也有记忆（每节点存 3–5 条痕迹，重访注入）。

## D12 存档：每日快照 + 文件导入导出
**决定**：结算时自动快照，支持回到指定天；分享与备份走 JSON/zip 文件。
**否决**：云同步、账号、联机、社区服务器 —— 出范围，且与 D1 冲突。

## D13 明确不做
- 瓦片地图与角色行走动画（见 D4）
- 逐 tick AI 模拟与 NPC 间真实对话（见 D6）
- 完整经济模拟 —— 简化为少量数值 + 规则化流转
- 云端任何形态（见 D12）
- 语音与生图 —— 推迟至阶段 10，但适配器接口在阶段 0 定形

## D14 角色内容使用项目原生格式
**决定**：角色卡、世界书与预设只承诺兼容本项目 schema 与导出包格式，不承担第三方内嵌卡片格式的解析。
**理由**：保持导入校验、资产边界和迁移规则一致，避免第三方格式变动扩大维护面。

## D15 AI 导演
**决定**：事件池 + 按（地点, 天, 时段）三元组排程 + 冷却 + 好感区间门槛 + 张力曲线 + pending 队列（可预约数日后的事件以制造伏笔）。张力由平静天数曲线与事件声明的确定性偏移组成，事件可声明张力门槛、张力权重增益与触发后的偏移；所有计算由内核持有，不依赖 AI。
**理由**：区分"带地图的 AI 聊天"与"一个游戏"的关键。
**要求**：数据驱动，用户可编写并分享事件包。

## D16 用约束制造生活感
**决定**：定期房租/结算、玩家自身日程（上班时段/店铺营业时间）、三条常驻软目标（住所升级／关系推进／事业线）、每日结算页。
**理由**：绝对自由会产出空虚。"翘班去见他"需要先有班可翘。
**衍生**：玩家开店/打工绑定节点并占用时段，玩家自身成为地图上的一个点，角色会路过来找 —— 反向偶遇。
**阶段 8 落地**：岗位规则只保存工资 stat key 与开班 slot id，工作契约只绑定规则和节点。招聘叙述不能决定工资；玩家必须按时到岗并消耗通用 `work.slotCost`，工资由 `onDaySettle` 写入配置货币对应的 stat。错过班次的代价是失去当日工资，不设置会卡死游玩的强制惩罚。

## D17 手机竖屏 + 地图 App 信息架构
**决定**：界面采用 mobile-first 竖屏布局，地图作为默认首页和主要视觉锚点；聊天、晨报、日记、物品与设置通过地图 App 式底部导航、卡片和抽屉进入。
**理由**：项目的核心动作是"走出去"，地图必须在信息架构上优先于聊天；竖屏优先能约束信息密度并保证触控可用，同时保留宽屏响应式扩展。
**约束**：优先适配约 360–430 CSS px；主要触控目标不小于 44 CSS px，支持安全区、单手滚动，不依赖悬停；阶段 4 前只保留结构、CSS 变量和组件插槽，不做装饰性美化。
**不改变**：地图仍使用 D4 的 SVG 图结构/热点图方案，不引入瓦片地图或行走动画。

## D18 日记：API 总结 + 本地回退 + 用户可编辑
**决定**：日结时优先调用一次 `summarize_day` 生成日记；未配置或调用失败时，由代码根据确定性 `DailyFacts` 生成不编造事实的本地摘要；生成后的日记允许用户直接编辑并保存。
**理由**：AI 更适合把事实组织成有情绪的文字，但离线可玩和记忆压缩不能依赖 API；用户编辑是纠正叙述错误、保留个人记忆的最终入口。
**约束**：API 只返回日记文字，不能写入任何状态事实；编辑后的文本在后续 prompt 中作为权威日记使用，并记录 `editedAt`；每天最多一次自动调用，重生成必须由用户显式触发。

## D19 添加到主屏幕后的全屏体验
**决定**：网页支持安装到设备主屏幕后以 PWA `standalone` 模式运行，默认隐藏浏览器地址栏与工具栏，并正确处理安全区；普通浏览器标签页访问保持兼容。
**理由**：项目的主要使用场景是手机竖屏，主屏幕启动后的沉浸式体验应接近原生地图 App，同时不引入后端或账号系统。
**约束**：需要 manifest、合适的 viewport/主题色与安全区 CSS；离线缓存策略另行评估，不在当前阶段顺手扩展。

## D20 聊天采用“发送消息 / 生成回复”双动作
**决定**：输入区提供两个明确动作。发送消息只入队并本地保存，不调用 API；生成回复将最后一条助手回复之后的用户消息合并为一次请求；已有完整对话时，空输入也可显式请求角色继续回复。
**理由**：单个“发送”按钮在“有文字时追加、空白时生成”之间切换含义不清楚，也不利于用户判断何时产生 API 成本。双动作让连续补充信息和真正发起请求都可预测。
**约束**：请求前保存用户消息；等待首 token 与流式生成状态分开显示；失败保留消息供重试。

## D21 设置、调试与普通存档边界
**决定**：底部导航使用“地图 / 聊天 / 资料 / 设置”，Provider 管理放在独立设置页；调试面板作为正式版高级能力保留，在设置中默认折叠。普通 `save.zip` 永不导出或覆盖 Provider 配置与 API key。
**理由**：聊天与连接配置是不同工作流；调试能力对高级用户和内容作者有长期价值，但不应占据一级导航。密钥与可分享存档必须保持明确隔离。
**后续**：全局备份可覆盖非密钥 Provider 元数据；如允许密钥导出，必须另做显式选择与加密格式设计。

## D22 无头调参与可复现测试
**决定**：确定性 `core/` 必须同时支持浏览器与 Node 无头运行。批量模拟复用同一套时间、事件、相遇、话题与结算逻辑，通过固定 seed、动作策略、Mock provider 和版本化 scenario 驱动。
**理由**：`20 seeds × 60 游戏日`一类长程统计无法依赖手工试玩；只有复用正式内核，才能让相遇分布、最长未见间隔、话题枯竭、lead 忽略率、事件间隔与张力曲线成为可信回归指标。
**边界**：`core/` 不访问 DOM、IndexedDB 或网络；持久化只在 `data/`，AI 调用只在 `providers/`。模拟推进必须真实经过公开内核流程；直接落点仅用于构造起始条件，输出可导入的普通存档 zip，不作为过程验证证据。
**分期**：阶段 2 建立运行器、30 天模拟推进和直接落点；阶段 4 加相遇指标，阶段 5 加话题指标，阶段 6 加 lead 指标，阶段 7 加事件/张力指标并形成完整 60 天报告。

## D23 移动端后台行为采用恢复优先
**决定**：不承诺网页或 PWA 在 Android / iOS 后台持续运行、维持流式请求或定时唤醒。阶段 9 实现可靠的状态落盘、回到前台后的恢复与中断重试；阶段 10 再评估系统通知和移动端壳允许的受限后台任务。
**理由**：两套移动系统都会冻结或终止后台网页，Service Worker 也不是常驻进程；纯前端静态站点无法跨平台保证“后台保活”。假装请求仍在进行会导致重复生成或重复应用 ops，破坏确定性状态。
**降级**：离开前台前保存输入、消息和请求标识；恢复时检查结果是否完整。无法确认完成的请求标为中断，由用户显式重试，并确保同一响应的 ops 最多应用一次。
**平台边界**：真正的长期后台执行若依赖服务端推送或常驻服务，将与 D1 冲突，不纳入网页版本；移动端壳能力必须分别在 Android 与 iOS 真机验证后才能写入支持清单。
**实验性保留**：音频辅助保活不能作为可靠性保证，但可在阶段 9 提供默认关闭的显式开关，只在活跃请求期间运行且最长 90 秒。必须披露耗电、媒体通知与平台差异，请求结束立即停止；Android / iOS 真机数据决定是否保留。
**否决**：用 Web Worker 或 Service Worker 常驻保活。Web Worker 随页面冻结；Service Worker 是事件驱动的短生命周期执行环境，不能可靠维持任意长流式请求。
**可实验但不承诺**：Service Worker 可作为单次请求代理，在生命周期允许时用 `waitUntil` 延长任务并把片段写入 IndexedDB；它不是常驻进程，任何实现都必须保留中断检测和前台恢复路径。
**暂不纳入**：一键部署云端 Worker。它可以在服务端代跑生成，但会引入后端与浏览器外的 key/内容处理，和当前 D1、铁律 7 冲突；若未来重议，必须先明确修改硬约束、威胁模型和用户告知。

## D24 物品定义先于库存事实
**决定**：任何库存写入都必须引用已存在的 `ItemDef`。AI 只能提出带 `itemId` 的 `give_item` / 礼物类 op；正文中出现“递给你”“收到礼物”等措辞本身不构成物品获得事实。
**理由**：如果允许 AI 仅凭文字创造物品，存档会出现无法显示、无法校验、无法导出的幽灵物品；同时会破坏“确定性内核持有事实”的铁律。
**约束**：物品定义由世界包、scenario、用户物品编辑器或受校验的数据包提供；op 注册表在 apply 前检查引用、数量、来源角色和规则条件。失败时保留正文，但库存不变，并在 Ops diff/状态提示中显示拒绝原因。
**随机性**：预先定义的是可用候选池，不是固定赠送结果。阶段 5 以后由确定性内核按角色偏好、tag、阶段、mood、事件条件和 seed 选择候选物品，再让 AI 描述已确认结果；禁止 AI 为制造惊喜临时创建目录外物品。
**分期**：阶段 1 落地目录引用校验、库存写入和 diff；阶段 5 礼物系统把角色、tag、阶段与 mood 纳入代码判定；阶段 7/8 再扩展角色自有物品的使用、携带、消耗和生活联动。

## D25 收藏、剧情道具与事件回顾解耦
**决定**：收藏系统记录玩家主动留下或获得的物品，并可在互动中作为“出示证物”的输入；剧情事件所需的关键道具、线索和条件事实不依赖收藏目录或玩家库存，必须由事件包/事件状态/内核事实单独声明和保存。
**理由**：收藏是玩家整理与回看的体验层，不能成为剧情逻辑的唯一数据库。否则一个未被收藏、被删除或仅存在于事件现场的道具会导致剧情失效。
**证物互动**：出示动作先由内核检查玩家确实拥有该收藏条目，再按角色/NPC、itemId、tags、事件阶段和条件选择确定性反应；AI 只描述已选结果。没有规则的物品可以展示，但不应凭展示动作自动改变数值或推进剧情。
**事件回顾**：事件触发后保存可回看的记录（事件 ID、标题、时间地点、参与者、选择、结果、摘要和叙事文本），可导出或删除回顾资料。删除回顾不撤销事件已应用的 ops、关系变化、物品获得或其他世界事实。
**分期**：阶段 5 先定义收藏出示接口与反应规则；阶段 7 随事件系统落地 `eventHistory`、回顾 UI、导出/删除和长度控制；阶段 10 再评估跨存档批量整理与完整性检查。

## D26 收藏展示字段可纠错，规则身份不可漂移
**决定**：物品进入收藏时可以根据实际获得来源生成标题、描述、tags 和获得信息；用户可以编辑或删除收藏展示内容。出示给角色/NPC 时，反应上下文包含角色个性、当前 situation、事件阶段、物品规则标签以及用户当前确认的展示描述。
**边界**：收藏展示字段的编辑是玩家事实，可以影响“别人看到的描述”和 AI 的措辞，但不能静默改变物品的稳定 ID、来源、所有权、功能效果或已经发生的剧情事实。功能性物品的规则标签/效果由内核或事件包持有；纯收藏品可以更自由地编辑。
**流程**：内核先校验玩家拥有该收藏条目，再按角色/NPC 和条件选择反应规则；AI 只根据已确认的上下文生成文字。没有匹配规则时可以描述观察或疑惑，但不得凭描述自动写入新状态。
**分期**：阶段 5 实现收藏条目生成、用户纠错和证物出示基础；阶段 7 接入角色个性、当前情况和事件上下文的反应规则；阶段 10 再评估更强的本地/外部模型辅助整理与批量纠错。

## D27 资料包与聊天数据分离
**决定**：资料预设支持多个条目作为一个预设包 zip 整体导入/导出，同时保留单项 JSON。普通世界存档导出提供是否包含聊天记录的显式选项；清除全部聊天必须是用户确认的独立操作。
**边界**：不带聊天的导出只影响导出包，不删除浏览器本地聊天；导入存档也不自动删除当前聊天。用户要从零开始时，导入后通过“清除全部聊天”显式执行。Provider 配置和 API key 仍不进入任何包。

## D28 偶遇触发点与可调参数
**决定**：偶遇不只发生在玩家到达地点时；玩家或角色离开地点、发生移动时也可以按概率触发偶遇。提供全局开关，关闭后不进行抽取。玩家准备离开地点时，可以选择“离开”，或留下并继续对方事件，选择结果由内核记录并可回放。
**理由**：移动途中的偶遇提供意外感，同时保留玩家对时间和事件的控制；离开借口是自然的拒绝表达，继续事件则允许玩家主动承担机会成本；开关满足想专注地图路线或只接受确定性相遇的用户。
**约束**：概率、权重、保底间隔、急事判定和两种选择的后果都必须是数据/规则配置，不能由 AI 临时决定。抽取使用固定 seed 的随机源；AI 只描述内核已选中的角色和选项。
**调参**：阶段 2 的 Node 无头 runner 负责快速跑批；阶段 4 加入相遇统计。调参应改配置/数据包并重跑回归，不改核心循环或 UI 逻辑。

## D29 世界快照回退与聊天记录边界
**决定**：阶段 2 的本地快照只恢复确定性世界存档，不自动删除或截断按角色保存的聊天记录。
**理由**：回退是可恢复的世界操作，聊天记录是用户内容；默认删除聊天会造成不可逆的数据损失。
**已知代价**：回退后聊天可能包含回退点之后的叙述，造成世界事实与对话上下文的时间线不一致。
**后续**：记忆系统成熟后提供“保留聊天 / 同步回退聊天 / 新建分支”等显式选项；任何同步回退都必须以用户确认为前提，不能静默丢弃消息。

## D30 已发现地点采用休闲移动规则
**决定**：玩家可点击前往任意已发现地点，不要求目标与当前位置直接相邻。内核在地图图结构上寻找最低时段成本路线；同区域边成本为 0，跨区域边使用 `travelSlots`。移动成本超过当天剩余时段时允许正常跨日结算，不作为失败状态。
**理由**：地图主要服务于休闲叙事和“想去哪里”的选择，不应让玩家为了多跳相邻节点重复点击，也不应把当天时段用尽表现成硬失败。
**开放时段**：`openSlots` 不阻止玩家移动到地点节点，但决定当前处于“正式进入”还是“附近外围”范围。开放时段可触发正式进入、营业和室内事件；未开放时只能触发附近外围的相遇或事件。范围由内核根据当前时段派生，AI 不得自行宣称已经进入未开放地点。
**边界**：未发现地点仍不可移动；地图编辑器继续保证图连通。移动、寻路和跨日结算均由内核执行，零 API 调用。

## D31 竖屏面对面场景只显示当前说话者立绘
**决定**：面对面相遇/聊天采用手机竖屏视觉小说壳。场景中最多可有 3 位角色，但任一时刻只渲染当前说话者的一张立绘；说话者切换时替换这张立绘，不同时显示两张或三张立绘。
**理由**：竖屏可用宽度不足以稳定容纳多人立绘；单活动立绘能保持构图、阅读顺序和移动端性能，同时保留多人对话关系。
**表现**：带 `speakerId` 的台词显示说话人名牌与台词；旁白不显示说话人名牌。多人互相发言不改写为轮流向玩家汇报。
**约束**：立绘仍为可选资产；面对面场景只读取当前单张立绘，缺少时立绘区域留空。头像不替代立绘；地图头像缺失时才使用 `accentColor + 姓名首字` 占位，任何缺图情况都不得报错。

## D32 相遇触发 UI 与进入后的聊天场景 UI 解耦
**决定**：地图底部相遇栏只负责展示“谁在这里”和触发“留下并对话 / 离开”等入口选择；确认进入后切换到独立的面对面聊天场景页。
**理由**：触发确认需要保持地图上下文，聊天阅读则需要沉浸式竖屏视觉小说布局；两者混在同一栏会限制后续立绘、旁白和选项扩展。
**范围**：阶段 4 实现聊天场景壳、单活动立绘和说话人/旁白显示；阶段 5 在该壳内接入话题树与分支选项。中间选项属于面对面场景，不与地图底部相遇栏混用。

## D33 面对面立绘与终端头像/地点字段分期
**决定**：阶段 4 提供地图图钉头像及缺头像时的首字占位，并提供面对面场景的单张可选立绘；阶段 9「有终端」再提供联系人/消息列表头像、短气泡消息回复和联系人“所在地点”字段。
**理由**：面对面相遇是到场推进关系的核心；终端消息是远程维持关系的独立交互壳，不能把两种聊天形式混为一谈。
**边界**：阶段 4 的地点事实仍由内核和本地 presence 查询提供；只有终端联系人卡片中的地点展示留到阶段 9。头像与立绘继续遵守 D10 的分离显示规则。

## D34 地点场景背景图作为阶段 4 后续资产切片
**决定**：地点可配置一张可选场景背景图，进入面对面聊天场景时按当前地点加载；缺图时保持纯色/主题背景，不显示错误占位。
**分期**：这是阶段 4 的后续垂直切片，现已完成。`MapNode` 增加可迁移的 `sceneBackground` 资产引用，并同步导出包、编辑器上传和场景加载。
**理由**：背景属于地点的持久化世界事实，必须遵守资产 id/外链约束并保证旧存档可读；本切片升级到 schema v7，并附 migration 和 migration 测试。

## D35 玩家多面具身份与世界存档单绑定
**决定**：玩家可以在本地身份库维护多个“面具身份”，但每个世界存档只绑定一个当前身份；切换身份是显式的存档设置操作，不由 AI 或聊天内容隐式改变。
**范围**：身份至少包含稳定 ID、管理名称、对话框显示称呼和可注入提示词的自我描述；当前存档保留绑定 ID，读取时解析到身份内容。旧存档只有 `player.persona` 文本时必须保留原文，并提供明确的补创建/绑定入口；自动生成默认身份可作为后续兼容性增强。
**分期**：在阶段 5 话题树之前完成，作为阶段 4 后续/阶段 5 前置基础切片；与地点背景图一样需要明确 schema 版本、migration 和测试。
**理由**：身份会影响面对面叙事和后续话题解锁，但不应散落在聊天输入中；“多个身份、单存档绑定”既保留复用能力，又避免一个世界同时混入多个玩家事实。

## D36 告别、主动离开与玩家挽留分期
**决定**：阶段 5 的面对面事件允许玩家主动告别；角色也可以根据日程、处境或事件规则提出离开。角色提出离开后，玩家仍可在自由输入中编辑挽留、转移话题或无视并放任对方离开。
**分期**：阶段 4 只提供相遇入口和聊天壳；告别信号、挽留结果与离开记录放在阶段 5 话题/事件切片中实现。
**状态边界**：角色“准备离开”是内核可追踪的事件状态，不由 AI 直接写入；AI 只能叙述并提出白名单 ops，内核校验后记录 `continued` / `left` 等结果。玩家自由输入本身不自动回复、不自动改变状态，仍需显式发送并生成回复。
**理由**：告别是对话分支而非地图移动，不能把它简化成当前相遇栏的二选一；保留自由输入能让玩家决定挽留方式，也允许沉默和放任离开，且不增加行动点成本。

## D37 说话人/旁白采用兼容式行标记
**决定**：阶段 4 支持 `kind` / `speakerId` 结构化消息元数据，同时支持 `[说话人:角色名] 台词` 与 `[旁白] 内容` 的逐行标记；未标记的旧助手消息按旁白显示，未标记的用户消息显示为玩家称呼。结构化消息中的说话人 ID 由本地角色/玩家标签解析，不把 ID 直接展示给用户。
**理由**：先解决视觉小说壳中的阅读区分，同时不要求旧聊天记录迁移，也不让不支持结构化输出的 Provider 失效。
**后续**：阶段 5 再将标记收敛为带 `speakerId` / `kind` 的结构化话题与事件消息；解析失败时保留正文并按兼容规则渲染。

## D38 玩家称呼显示是本地 UI 偏好
**状态**：已被 D35 取代。
**原决定**：玩家可在聊天页选择显示“你”或当前存档的玩家名字；该选择只影响 UI 名牌，不改变 `world.player.name` 等世界事实，也不进入 API 状态 ops。
**取代原因**：称呼现在属于可复用的玩家面具身份；每个世界显式绑定一个面具，面具的 `displayName` 同时作为对话框名牌和提示词中的玩家身份事实。旧的全局 UI 偏好设置仅为兼容读取而保留，不再作为新界面入口。

## D39 大规模 UI 打磨安排在阶段 4 验收后
**决定**：阶段 4 开发期间只修复影响可用性、信息层级和移动端布局的结构问题；颜色、动效、装饰、组件重排和整体视觉统一等大规模 UI 打磨，安排在阶段 4 功能验收完成后、阶段 5 话题树接入前集中进行。
**理由**：阶段 4 会固定地图、相遇入口、竖屏面对面聊天和立绘/旁白层级。等这些交互边界稳定后再统一视觉，能避免阶段 5 分支选项和对话状态接入时反复返工，同时不把核心状态逻辑与视觉重构混在同一提交中。
**边界**：UI 打磨不改变确定性内核、存档 schema 或 API 调用边界；若需要新增交互事实，仍按正常阶段切片单独设计和迁移。

## D40 玩家代写与旁白人称由预设控制
**决定**：内置格式契约只固定说话人/旁白标记、状态所有权和 ops 边界，不写死 AI 是否可以代写玩家。资料库提供“基础叙事控制”预设包，默认包含“玩家代写方式”和“旁白人称”两个独立条目。
**顺序**：预设包数组顺序就是实际 prompt 顺序；启用条目整体位于内置 prompt block 之前，首项视为核心预设。用户可以启停条目并上下移动，停用不删除内容。
**兼容**：旧预设条目迁移时默认启用；预设包导出格式升级到 v2，仍可导入 v1 包。该变化属于本地资料 schema，不修改 `SaveFile.world`。

## D41 对话颜色绑定说话人而非当前活动角色
**决定**：每条结构化台词根据本地解析出的 `speakerId` 使用该角色自己的名牌颜色；当前说话者切换只更换活动立绘，不重染历史台词。旁白保持中性色，玩家台词使用独立玩家色。
**配置**：正式角色可以在当前世界角色资料中设置 `visuals.accentColor`。未设置时，本地代码按稳定角色 ID 从默认调色板分配颜色，并尽量避免同场正式角色撞色；半正式 NPC 继续使用中性色。
**边界**：颜色是显示配置，不参与关系、日程或事件判定，不调用 Provider，也不需要修改存档 schema。

## D42 多人场景以玩家为叙事锚点并显式标记受话对象
**决定**：面对面 prompt 在单角色资料之前注入完整场景角色表，明确玩家是叙事主角与旁白视角主体，区分主要聊天角色和其他在场角色。旁白具体使用第一、第二或第三人称仍由预设决定，不在内置契约中锁死人称。
**指代**：第一人称旁白的“我”、第二人称旁白的“你”和第三人称旁白中的玩家称呼都指玩家；第三人称代词有歧义时使用面具称呼。角色台词中的“我”只指当前说话人，台词中的“你”必须能从姓名、动作、视线或上下文明确解析到受话对象。
**多人互动**：非玩家角色可以互相交谈，也可以插话、抢答或暂时忽视玩家，但注意力转移和介入动作必须用旁白明确呈现。禁止在角色向玩家提问后，让另一角色无提示地像玩家一样作答，也禁止让玩家从场景中静默消失。
**边界**：该约束只处理角色身份、叙事锚点和受话对象一致性；是否允许 AI 代写玩家仍由 D40 的用户预设控制。本切片不修改 schema、不增加 Provider 调用。

## D43 分段按钮等待期间显示非消息型进度
**决定**：面对面回复流开始前显示“正在生成第一段”；第一段已显示但回复流或状态整理尚未完成时，在后续“下一段”按钮的同一位置显示“后续内容生成中”。完成后若有更多段落则原位替换为按钮，只有一段时直接移除。
**表现**：进度标识采用中性色和轻量三点动画，不显示角色名牌、不预判下一位说话人，并遵守系统的减少动态效果设置。它只表示界面生成状态，不作为聊天消息持久化。
**边界**：重试 ops 等非回复生成操作不显示该标识。本切片不改变 Provider 调用方式、流式内容或分段规则。

## D44 阶段 4 末集中重做地图交互壳
**决定**：阶段 4 功能验收完成后，再集中进行地图 UI 打磨。地图主区域尽量扩展为全屏，移除项目标题但保留日期、时段、当前位置和地图状态；所有地图工具迁移到底部可拖拽抽屉，底部五项主导航保持原样。抽屉至少支持收缩、半展开和展开，点击 Graph 锚点或 Hotspot 图钉时自动展开地点详情，地图拖动、缩放和视野调整不因抽屉遮挡而失效。
**尺寸目标**：Graph 模式的“重置视野”默认状态放大地点锚点，在场角色头像按同一比例同步放大；Hotspot 模式默认图钉整体放大，角色头像保持与图钉协调的比例。具体像素值留到 UI 实现时按手机、平板和桌面视口实测确定，不写入世界状态。
**分期理由**：这是结构性 UI 和信息层级调整，不改变确定性内核、地图 schema、移动规则或 API 边界；提前改动会增加地图交互验收阶段的返工风险。

## D45 长期偶遇使用固定 seed 无头回归
**决定**：阶段 4 用纯本地无头 runner 对偶遇做长期分布回归，默认 `20 seeds × 60 游戏日`。runner 只克隆世界快照、按确定性路线选择已发现节点，并调用现有相遇选择/记录函数；输出每个角色的相遇次数和最长未见天数。
**验收**：相同 seed 与输入必须产生完全相同的报告；在配置的 `guaranteeAfterDays` 范围内，角色不能永久不被选中；不同 seed 的结果应存在合理差异，不能所有运行都集中为同一角色序列。
**边界**：该 runner 位于 `src/dev`，不进入生产 UI，不调用 Provider，不增加 schema，不改写核心时间循环。调参只修改测试配置或数据包后重跑回归。

## D46 地图抽屉连续跟手并保持独立
**决定**：地图工具栏和地点详情使用独立的 0–1 展开进度，而不是只在收起、半展开、完全展开三个离散档位之间跳转。拖动标题栏时，抽屉高度随手指位置实时变化；普通松手保留当前高度，快速上滑吸附到完全展开，快速下滑吸附到收起。地点详情进度归零时直接关闭并清除选中地点，工具栏不受影响。
**边界**：抽屉通过覆盖层遮挡地图，不参与地图布局，不改动地图缩放、偏移或世界状态；该切片只改变本地 UI 交互，不修改 schema、不增加 Provider 调用。系统启用 `prefers-reduced-motion` 时取消拖动后的过渡动画。

## D47 阶段 4 验收关闭与阶段 5 起点
**决定**：截至 2026-09-07，阶段 4 的路线图交付和验收标准全部完成，下一阶段从 `TopicTree` 话题树切片开始。阶段 4 后续只接受阻塞性缺陷修正，不再追加新的功能范围。
**保留事项**：`.txt` / `.docx` 导入按普通文本处理，正文完整写入角色卡、世界书或预设条目的描述框，不做字段映射；该功能属于阶段 5 之后的资料兼容性增强，不修改阶段 4 schema。

## D48 话题树结束后才解锁手动对话
**决定**：面对面场景进入后先使用 TopicTree 模式并隐藏输入框。只有当前可选话题全部使用、且没有待解锁话题时，才解锁手动输入；`terminal` 话题按推进型选项处理，点击后结束场景。
**理由**：先让结构化话题承担低延迟、可经营的关系推进，再把自由输入作为话题树结束后的开放式互动，避免两套入口同时抢占叙事节奏。
**边界**：话题按钮点击不调用 API；切换到手动模式是本地状态变化，不消耗行动点。

## D49 手动回复支持带要求的文字重生成
**决定**：手动对话模式下，用户可以针对最新回复填写重新生成要求并显式发起一次新请求。第一版重生成只产生叙述文字，不重新应用原回复已经成功执行的状态 ops；TopicTree 的固定 response 不参与重生成。
**理由**：允许用户纠正语气、长度和叙事方向，同时避免重新执行 ops 导致关系、物品或时间事实重复写入。
**边界**：重生成请求按用户操作计费和调用，不自动重试；若返回 ops，解析层丢弃并在调试面板记录警告。要回滚并重做状态，另行设计快照/分支流程。

## D50 记忆库只管理长期记忆，不删除固定话题树
**决定**：TopicTree 与历史对话保持固定；话题过程中经由确定性 op 写入的关系记忆、地点记忆或其他长期记忆，用户可在未来的可视化记忆库中手动编辑、归档或删除。删除记忆不会删除 TopicTree，也不会改写历史对话正文。
**删除策略**：默认先“归档/停用”并允许恢复；永久删除需显式确认。操作只影响未来 prompt，不回滚关系轴、flags、物品、事件或聊天事实。
**可编辑边界**：可编辑记忆正文、展示标签、置顶和是否注入；稳定 ID、发生日期、地点、关联角色以及已应用的状态事实不可通过记忆编辑改变。
**分期**：阶段 5 先保证记忆条目结构和来源可追踪，并提供按角色查看、逐条删除的最小记忆库入口；阶段 6/7 再增加归档/恢复、编辑、筛选、批量管理和导出边界。

## D51 iOS PWA 全屏采用安全区兼容，不改变地图信息架构
**决定**：保留阶段 4 已验收的顶栏、右上角工具图标、地图主体、抽屉和底部五项标签布局；在 PWA standalone 下通过 `viewport-fit=cover`、`100dvh`、安全区 inset 和根背景处理，让内容视觉上延伸到 iOS 安全区。
**边界**：普通 Safari 标签页的系统浏览器栏无法由网页隐藏；standalone 也不能移除状态栏图标和 Home Indicator，只保证内容背景与控件避让稳定。
**分期**：若白边影响可用性，可作为阶段 4 后的阻塞性兼容修正；否则放入阶段 9 PWA 视口兼容切片，并在阶段 10 做 Android/iOS 真机报告。

## D52 StoryScene 支持轻量大纲与电子小说阅读视图

**基础设计**：此前已提出超过 3 位参与者或明确需要多阶段推进的剧情使用独立 `StoryScene`，不扩张地图日常相遇的 3 人上限；该模块安排在阶段 7「有故事」，待 `EventDef`、`DirectorState`、事件回顾和阶段/条件基础稳定后作为独立垂直切片实现。

**本轮确认与补充**：用户确认接受上述分层，并补充了轻量大纲入口、系统预设和电子小说阅读视图的具体要求。

**大纲入口**：用户可以只输入关键词、短句或少量意图，让系统生成可审阅的剧情草案；也可以填写较完整的剧情大纲。轻量入口是默认友好的休闲路径，详细大纲是可选的精细控制路径。系统提供若干本地预设，用户选择后使用副本编辑，原始预设保持不变。

**状态边界**：关键词、大纲和预设只表达剧情意图、结构和叙事偏好，不直接写入关系、物品、时间、位置或其他世界事实。草案必须先展示并由用户确认，确认后才创建/启动剧情；进入条件、参与者到场、阶段转换和结果由确定性内核、事件包与白名单 ops 决定，AI 只产出叙述和 ops 提议。

**阅读界面**：`StoryScene` 使用独立的电子小说阅读视图，默认护眼主题；正文连续滚动，按章节/阶段分隔，选项嵌入阅读流，支持阅读进度与中途恢复。立绘或插图是可选资产，不成为多人布局的必要条件。主题切换属于本地 UI 偏好，不改变世界事实。

**分期理由**：阶段 5 先完成 TopicTree、关系和记忆基础，阶段 6 提供世界方向与钩子，阶段 7 才具备事件排程、阶段门槛、章节收束和事件回顾，适合承载用户大纲与多人剧情。实现时若新增 `StoryScene` 存档字段，必须在同一提交递增 schema、提供 migration、引用校验和测试。

## D53 相遇候选人与对话参与者分离

**决定**：地图相遇先由内核确定实际在场候选人，再由用户在正式进入前勾选本次对话参与者。参与者数量为 1 人时生成单人 TopicTree，2–3 人时生成多人上下文；进入聊天后参与者集合固定，移除角色切换入口。

**未选角色**：未被选入对话的在场角色仍保留为相遇事实，不自动从地图消失。之后是否离开或留在原地，只能由既有日程、时间推进、NPC 移动或事件包规则决定，不能由 AI 临时写入。

**状态边界**：相遇候选人和实际对话参与者是不同概念；后续若需要在结算、回放或关系统计中持久化两者，新增字段必须通过新的 schema migration 明确记录，不能改变既有 `encounterLog.characterIds` 的含义。

**理由**：先确定参与者再生成 TopicTree，可避免主要角色、多人上下文和树缓存身份不一致，也让用户对本次相遇的范围拥有清晰控制。

## D54 送礼反应采用普通对话调用，但事实由内核确认
**决定**：送礼只在 TopicTree 结束后的自由对话阶段开放。玩家送出礼物后，内核先校验目标角色、物品和库存，写入 `pending` 礼物记录并消耗/预留物品；随后复用一次 `narrate_main` 调用，让模型生成角色反应正文并提出 `resolve_gift` ops。内核只接受白名单反应并完成最终落库。
**调用边界**：每次实际送礼最多调用一次 API，不按 tick 或角色数量扩张；请求失败保留 pending 状态，用户可重试。TopicTree 的固定 response 不重新生成、不回滚。
**状态边界**：模型可以决定叙述语气、接受/拒绝/平淡等提议，但不能直接改库存、关系、时间或地点；`giftHistory` 的送礼事实、状态和最终反应由确定性内核持有。
**分期**：阶段 5 实现 pending/resolved 礼物闭环与普通聊天复用；若未来物品存在确定性的“特殊效果”，特殊资格仍需由物品目录和内核条件确认。

## D55 多人相遇送礼必须显式选择收礼角色
**决定**：多人相遇进入自由对话后，送礼面板在参与者超过一人时显示“送给谁”选择器。目标只能是本次相遇开始时锁定的正式参与者；一件礼物一次只能送给一位角色。
**状态边界**：送礼目标写入 `giftHistory.charId`，生成回应时以该角色作为 `resolve_gift` 的 actor；主要聊天角色只是对话记录与 TopicTree 的默认主角，不代表每次礼物的收礼人。
**分期**：阶段 5 先提供单件礼物的显式目标选择；群体礼物、多人同时回应和超过三人的剧情继续留给 StoryScene。

## D56 TopicTree 优先使用结构化输出并保留中转站降级
**决定**：`topic_tree` 任务在 OpenAI-compatible Provider 上默认请求严格 JSON Schema（Structured Outputs）；若中转站只支持 JSON mode，Provider 配置可切换为 `json_object`；关闭结构化输出时仍保留现有解析、schema 校验和失败重试。
**兼容边界**：中转站只有在透传 `response_format` 与 JSON Schema 字段时才能使用严格模式。只支持旧字段、重写请求体或拒绝未知字段的服务，应选择 JSON mode 或关闭结构化输出；Anthropic、Gemini、Generic 不被强行套用 OpenAI 请求字段。
**状态边界**：输出格式只约束模型返回形状，不授予模型写入状态的权限；TopicTree 仍须经过 `parseGeneratedTopicTree`，角色、地点、日期、数量和字段规则由内核确认。
**分期**：阶段 5 先接入 OpenAI-compatible 的任务级开关；后续再为 Gemini 的 `responseMimeType` / schema 和其他 Provider 增加原生适配。

**阶段 5 统计实现**：固定 seed 的话题统计位于 `src/dev/topic-simulator.ts`，仅用于无头调参和回归，不进入生产 UI，也不改变核心循环。

## D57 资料与设置采用图标启动器，但保留中文标签
**决定**：资料页和设置页未来改为类似手机主屏幕/电脑桌面的图标卡入口；每张卡始终显示“图标 + 中文名称”，不显示一行状态摘要。现有底部“地图 / 日程 / 聊天 / 资料 / 设置”主导航保持不变，图标启动器只负责页面内部分类与进入子功能。
**理由**：随着记忆库、收藏、事件回顾、Provider、调试等入口增加，图标网格比持续纵向堆叠更容易浏览；保留文字标签可避免图标语义不明确并兼顾无障碍。
**分期**：阶段 5–8 先稳定功能分类与入口名称；阶段 9「有终端」统一实现移动端/桌面端响应式图标启动器，不改变 core、存档 schema 或 API 边界。

## D60 向量记忆只作为外接检索索引
**决定**：向量记忆不在浏览器本地运行 embedding 模型，只通过用户明确配置的外部 embedding API 生成和查询向量；默认关闭、无 API 时退回本地结构化/关键词检索，不影响正常聊天。
**状态边界**：关系轴、时间、地点、物品、事件、记忆来源和注入开关仍由确定性内核持有。向量是可重建的派生索引，不能作为事实唯一来源，也不能直接写入世界状态。
**检索策略**：先按参与角色、地点、事件阶段、归档状态和注入开关做确定性筛选，再结合关键词、时间、重要性与语义相似度选取少量记忆进入 Prompt；删除、编辑、归档后立即排除旧索引，模型变更时允许整批重建。
**隐私与成本**：只有用户显式选择的 embedding Provider 才能接收待索引的记忆文本；界面显示 Provider、调用次数和失败状态。不得把向量 API 调用扩展成每个角色/每个 tick 的请求。
**分期**：阶段 6 先完成记忆元数据和零 API 检索接口；阶段 7 增加可选外部 embedding 的混合检索；阶段 9/10 再考虑终端入口、索引导入导出和跨存档重建。

## D67 向量记忆配置与索引留在浏览器本地
**决定**：阶段 9 在现有设置页提供独立的 OpenAI-compatible embedding 配置、显式启用开关、连接测试、调用/失败状态与当前世界索引重建。配置和 API key 保存在 Provider IndexedDB；向量按存档、角色和记忆 ID 保存到 Content IndexedDB，不写入 `SaveFile`，因此世界存档 schema 保持 v38。
**调用边界**：默认关闭；关闭、查看设置、浏览或管理记忆时均为零 API。启用后，仅在面对面回复生成或用户显式连接测试/重建时调用。单次回复只为主要角色发起至多一个批量 embedding 请求，并把查询与缺失/已变更记忆合并；其他在场角色使用本地检索，禁止按角色逐个请求。

**配置体验**：用户可显式点击一次“拉取模型”，从 embedding 请求端点对应的 OpenAI-compatible `/models` 端点执行一次 GET；不自动拉取、不清空手填模型。自定义 headers 只服务于额外鉴权、租户或区域字段，默认折叠在高级设置中，既有配置继续保留并参与连接测试、模型拉取和 embedding 请求。
**事实与降级**：向量只参与通过角色、归档和注入开关筛选后的排序，不持有时间、地点、关系或剧情事实。删除、归档、关闭注入、修改正文或切换模型会立即排除不匹配缓存；请求失败时继续使用确定性关键词检索，不阻断聊天。

## D61 可编辑聊天与记忆来源一致性
**决定**：玩家台词与角色回复均可通过长按/右键菜单编辑或删除；送礼、收藏出示等系统生成台词不可改写。聊天记录操作只影响正文，不回滚已经应用的关系、物品、时间或事件事实。
**记忆一致性**：v14 为关系记忆增加可选的来源聊天消息索引。编辑或删除一条聊天记录时，内核移除该条及之后由本次角色聊天产生的带来源记忆；没有来源索引的旧记忆保留，避免误删无法追踪的历史。下一次生成回复使用编辑后的完整上下文，由模型重新提出新的 `add_memory` ops。
**调用边界**：编辑、删除和记忆清理均为本地零 API；不会因为编辑自动触发生成请求。若用户需要补写记忆，必须显式继续对话并生成回复，或在记忆库手动管理。

## D58 角色主动靠近玩家是可覆盖的默认预设
**决定**：小小地图的产品默认基调是“角色主动靠近玩家”。普通聊天和轻互动默认不以挫败式拒绝为主要反馈；忙碌、心情和关系阶段用于改变回应方式、投入程度、距离感及后续邀约。玩家是可以接受、拒绝或暂缓角色靠近的叙事主角，而不是需要不断答题讨好角色的攻略者。
**可覆盖边界**：该基调不写死进 `format_contract`、确定性内核或不可修改的 prompt block，而是作为“基础叙事控制”预设包中的独立“角色主动性”条目默认启用。用户可以编辑、禁用或用其他预设覆盖，以塑造疏离、对抗、慢热等不同氛围。
**状态边界**：预设只影响叙述倾向，不能改变时间、地点、关系轴、物品、Appointment 或其他事实，也不能绕过 ops 白名单与条件校验。内核不实现“忙/心情差/阶段不足就自动拒绝玩家”的硬判定。
**兼容**：已有本地基础预设包升级时只补入缺失的“角色主动性”条目，不覆盖用户已经修改或关闭的旧条目。

## D59 世界观货币名称由经济配置提供
**决定**：货币的数值仍由确定性内核的通用 `stats: Record<string, number>` 持有，货币名称、符号、小数位和对应 stat key 由世界/经济配置提供，不在 core 或 UI 中写死“金币”等名称。
**推荐结构**：经济配置提供 `defaultCurrencyId` 与 `currencies` 映射；每种货币包含稳定 ID、展示名称、可选符号、小数位和对应的 ASCII `statKey`。单货币世界只配置一项，多货币世界按货币 ID 分开记账。
**边界**：AI 只能叙述已确认的金额和货币名称，不能创建货币、改变余额或绕过经济规则。收入、支出、工资、租金等事实仍由白名单 ops 与规则写入；UI/Prompt 从配置读取展示名称。
**分期**：阶段 8 经济系统落地时加入该配置并递增 schema、提供 migration 与测试；阶段 5 不提前引入经济字段。

## D62 租房事实使用 stat 引用并在日结时非阻断扣款
**决定**：租约结构只保存住所节点、租金规则 ID 和下次到期日 stat key；余额、租金、周期和到期日数值均保存在 `player.stats`。货币名称、符号、小数位与余额 stat key 从 `world.economy` 读取。
**签约边界**：晨报广告只提供入口和叙事文字，不能把 AI 输出的金额直接写入合同。用户确认后，由独立的本地经济 op 校验已发现节点、货币、租金规则和 stat，再写入 `homeNodeId` 与唯一生效租约。
**结算边界**：`onDaySettle` 触发内部经济 op；到期时扣除对应余额、推进下次到期日，并把带 `currencyId` 的交易写入日结记录。默认货币继续同步旧的 `income` / `expense` 汇总以兼容现有结算视图。
**不足余额**：允许余额为负，不阻断结算、时间推进、移动或对话，也不制造失败状态。欠款规则、退租、买房和住所升级必须作为后续独立切片接入。
**成本**：签约、查看条款、扣租和读取结算全部纯本地，不增加 API 调用。

## D63 体力使用通用 stat 与成本表
**决定**：体力不新增专用数值字段。`world.economy.energyRule` 只保存当前值、上限、休息恢复量和启用开关对应的 stat / flag key；实际数值继续由 `player.stats` 与 `player.flags` 持有。行动消耗从既有 `ActionCostTable.energyCost` 读取。
**默认规则**：默认体力 6/6，休息恢复 2；跨区域移动、工作、探索分别消耗 1、2、1，区内移动和休息不消耗。体力不足只阻止对应行动，不是失败状态；休息保持零体力成本，避免资源锁死。
**开关**：设置页可关闭体力限制。关闭时所有行动的有效体力成本为零，但当前体力数值不重置；重新开启后继续使用原值。该设置复用现有设置页，不新增页面入口。
**状态边界**：UI 本地行动与叙事可提出的 `advance_time` / `move_player` ops 必须经过同一确定性体力校验；AI 不能直接决定消耗、恢复或绕过成本。内部 `spend_energy` / `restore_energy` / `set_energy_enabled` ops 不暴露给叙事 Provider。
**兼容与成本**：v35→v36 migration 补齐成本表、默认 stats、flag 与规则引用，并保留既有 `slotCost`。全部计算纯本地，不增加 API 调用。

## D64 店铺营业通过角色日程形成反向偶遇
**决定**：店铺规则保存稳定 ID、展示名、可营业时段和累计营业天数 stat key；玩家经营权只保存店铺节点与规则 ID。接手店铺必须由用户确认后的本地 `accept_shop` op 写入，广告正文不能创建店铺或决定规则。
**营业约束**：玩家只能在规则声明的时段、店铺绑定节点开始营业；营业使用独立的 `operate_shop` 行动成本并占用时段、消耗体力。每日营业事实使用通用 flag，日结后清理并累加规则指向的普通 stat，避免为事业进度增加硬编码数值字段。
**反向偶遇**：营业覆盖时段内，只从现有正式角色与半正式 NPC 的确定性日程筛选到店者，并写入 `trigger: 'shop_visit'` 的普通相遇记录。上门相遇复用现有地图相遇与面对面对话流程；没有已排程访客时营业仍成功，AI 不得临时创造到店事实。
**边界**：本切片不实现商品目录、库存、定价、随机客流或销售收入，不增加 Provider 调用，也不新增页面入口。v36→v37 migration 补齐默认店铺规则、`operate_shop` 成本和累计营业 stat，旧存档继续可读。

## D65 住所升级使用数据驱动等级并在日结完成
**决定**：住所等级与升级路径属于 `world.economy` 数据包，不在 core/UI 写死等级名称、费用或效果。租约只保存当前 `tierId`；升级规则保存稳定 ID、起止等级、货币 ID 与费用 stat key，费用数值继续由 `player.stats` 持有。
**安排边界**：玩家必须位于 `housing.nodeId` 且余额足够，才能通过用户确认的本地 `request_housing_upgrade` op 安排升级。安排不消耗时段、不调用 Provider、不立即扣款；同一天最多安排一条升级，重复或跨等级请求必须被白名单校验拒绝。
**结算边界**：`onDaySettle` 先执行内部 `settle_housing_upgrade`，再执行房租、工资和店铺营业结算。成功时扣除配置货币、切换 `housing.tierId`、写入 `housing_upgrade` 交易并更新 expense 与日记；余额不足或规则失效只拒绝该项，不阻断时间推进、移动、对话或其他结算。
**入口与兼容**：升级详情复用日程页的住所折叠区域，不新增页面入口。v37→v38 migration 为旧租约补 `basic` 等级、默认等级/升级规则与默认费用 stat，并保留旧存档事实。

## D66 常驻软目标从既有事实实时派生
**决定**：住所、关系、事业三条常驻软目标使用稳定 ID `housing` / `relationship` / `career`，由日程页从现有 `WorldState` 事实实时派生，不新增 `goals` 存档字段，不递增 schema。
**内容边界**：住所目标读取租约等级与可用升级规则；关系目标读取正式角色和当日关系事实；事业目标读取工作/店铺契约及当日完成 flag。目标只提供当前可推进方向和已推进状态，不是胜负条件，不写入数值，不改变时间、位置、关系轴或经济事实。
**交互边界**：目标展示复用日程页，不新增页面入口；查看目标为纯本地零延迟查询，不调用 Provider、不消耗时段。无业、无住所或尚未遇见角色时仍显示可推进的开放目标，不能把玩家锁死在某条生活路线。
**验证**：阶段 8 最终无头回归继续使用固定 seed 的 30 日时间模拟，并额外验证三条目标顺序稳定、事实变化后状态可预测、旧 schema v38 存档无需迁移。

## D68 阶段 9 UI 使用可换皮的全灰阶系统令牌
**决定**：阶段 9 的系统 UI 默认只使用黑、白、灰令牌，成功、警告与错误也通过灰阶明暗、文字和图标区分；用户上传的地图背景、头像、立绘及角色自定义名牌色属于内容资产，保留原色。灰阶值集中在 CSS 变量中，组件不得新增零散业务色值，以便未来按世界观替换主题包。
**入口命名**：桌面图标只显示约两字的短标签，设置桌面使用“身份 / 模型 / 向量 / 路由 / 显示 / 规则 / 隐私 / 调试 / 开发”；进入子页面后继续显示完整标题，不附加图标说明或悬停说明。
**主导航**：底部五项顺序改为“日程 / 聊天 / 地图 / 资料 / 设置”。本决定只覆盖 D57 中旧的排列顺序，不改变五个既有入口、内部页面状态或零 API 查看边界。
**iPhone 分期**：现有 `viewport-fit=cover`、standalone manifest、`100dvh` 和安全区 inset 继续保留；资料与日程桌面迁移完成后再做独立 iPhone PWA 兼容切片，阶段 10 提供 Android/iOS 真机报告。

## D69 阶段 9 资料桌面先接入本地资料与终端占位
**决定**：资料主导航保持单一入口，桌面首屏以 12 个同级图标入口承载消息、联系人、通话、音乐、记忆、收藏、背包、角色、世界书、预设、多人剧情和存档。终端相关入口暂时只提供完整子页面壳与本地占位状态，后续终端切片直接在这些入口内接入，不新增底部导航或二级“终端”入口。
**边界**：角色、世界书、预设、背包、存档和既有记忆/收藏内容复用原有本地逻辑；消息、联系人、通话、音乐占位页不读取远端数据、不调用 Provider、不改变世界事实。桌面进入、子页面返回和底栏切换只维护应用内 UI 状态，保留原编辑现场。
**兼容**：本切片不修改世界存档 schema（继续 v38），不新增 API 调用，不改变确定性内核或 AI ops 边界。角色头像与立绘上传入口保留；角色名牌颜色的存储字段继续读取以兼容旧存档，但本资料桌面不提供颜色编辑入口。

## D70 桌面图标使用中性玻璃灰阶样式
**决定**：设置与资料桌面图标统一使用 Lucide 单色线性图标、固定尺寸的圆角方形底板、半透明灰阶表面、细边框、轻微阴影和局部背景模糊。所有历史 tone 名称继续作为兼容类名保留，但不再产生不同颜色；悬停和键盘聚焦只提高表面不透明度与边界对比。
**适配边界**：不读取墙纸像素、不增加亮度采样或主题状态；玻璃底板只提供局部遮罩和稳定对比度，未来墙纸或世界观换皮仍通过 CSS 变量替换。图标标题、徽标、网格尺寸和入口状态保持不变。

## D71 墙纸亮度驱动桌面图标灰阶前景
**决定**：在保留 D70 玻璃底板、圆角、模糊和阴影结构的前提下，桌面启动器可接收本地墙纸 URL，使用浏览器本地 Canvas 采样整体亮度，并将图标线条、标题、边框和阴影映射到非极端灰阶。深色墙纸使用浅灰至近白，浅色墙纸使用深灰至近黑，中间亮度使用中灰；不使用纯黑或纯白作为自适应结果。
**失败回退**：没有墙纸 URL、图片加载失败、Canvas 读取被跨域策略阻断或采样结果无效时，回退到 D70 的固定深灰前景。采样只发生在桌面启动器接收到新的墙纸 URL 时，不调用 Provider、不发送图片、不修改 schema。
**接入边界**：本切片只提供启动器的 `wallpaperUrl` 可选接口，不新增墙纸设置入口；后续墙纸切片负责从本地资产或外链生成 URL 并传入设置/资料桌面。

## D72 阶段 9 首个垂直切片先做联系人与好友申请
**决定**：终端按“联系人与好友申请 → 文本消息/引用/贴图 → 双向转账 → TTS 语音消息 → 本地通话壳”的顺序实施。首个切片复用资料桌面的既有“联系人”入口，不新增底部导航或二级终端入口。
**数据边界**：SaveFile 从 v38 升至 v39，新增 `world.terminal` 并一次性预留好友申请、消息线程、转账请求和通话记录容器；v38→v39 migration 只初始化空容器。联系人候选包含当前世界中已生成的正式角色、半正式角色和 NPC。
**操作边界**：我加 TA / TA 加我由玩家在本地选择方向，申请状态迁移必须幂等；接受、拒绝、撤回不消耗时段、不改变关系轴、不触发剧情，也不调用 Provider。地点与头像只读取现有确定性状态和本地资产引用。
**后续约束**：消息、转账、TTS、通话不在本切片实现；远程终端始终只能维持关系，不能推进关系、预约、事件或深度剧情。

## D73 终端消息与面对面聊天分离
**决定**：消息 App 只允许已接受好友进入线程，文本、贴图与引用保存到 v39 已预留的 `world.terminal.messageThreads`，不复用面对面 `ChatRecord`。新建“我加 TA / TA 加我”申请在同一个本地确定性操作中完成接受，普通界面只显示“已通过”，不暴露“模拟 TA 接受”动作；申请方向和日期继续保留为确定性上下文。旧存档的 outgoing pending 在读取时按已通过处理，旧 incoming pending 保留玩家接受或拒绝的原始意图。
**引用与资产**：引用只能指向同一终端线程，保存稳定消息 ID、类型与本地预览。贴图可使用外链 URL 或本地文件；本地二进制进入 Assets IndexedDB，SaveFile 只存 `AssetRef`，导出时打包引用资产，禁止写入 base64。
**API 与事实边界**：查看、发送文本、引用和贴图均为零 API。只有玩家显式点击“生成回复”才调用一次现有文本 Provider；Prompt 可读取谁先发起好友申请。模型回复可附带唯一白名单 op `terminal_transfer_proposal`，其余 op 全部拒绝；该 op 只创建待收款，不得推进关系、预约、事件、位置、时间或深度剧情。
**界面结构**：消息 App 首屏只显示已有消息线程，并按最后消息的确定性日期和时段倒序排列；没有消息的好友从联系人页进入并发送第一条消息。线程使用头像与左右灰阶气泡，气泡只显示消息内容，不附加世界日期/时段；线程顶部只显示联系人名称。底部保留输入、发送、生成回复、表情和更多图标；Enter 发送、Shift+Enter 换行。当前线程 ID 与每位联系人的未发送草稿仅保存为 localStorage UI 偏好，切换底栏后恢复，不进入世界存档。对话框和输入栏在消息页面剩余高度内贴近底部导航布局，避免额外留白或被底栏遮挡。
**语音入口**：用户侧“合成并发送语音”入口从消息线程移除，但已有语音消息、音频资产和语音 Provider 设置继续保留并可播放或管理。

## D74 终端转账采用双向待确认模型
**决定**：终端消息 App 在 v39 的 `transferRequests` 中记录双向转账。玩家向已接受好友转账时，由本地白名单校验货币、金额精度和安全数值后立即扣除玩家余额并保存 outgoing 完成记录；好友向玩家转账时只保存 incoming pending 提议，玩家显式接受后才入账，也可拒绝。

**幂等与边界**：接受、拒绝和重复点击均为幂等操作；转账不推进关系、时间、地点、预约、事件或深度剧情。非好友、错误联系人、无效货币、非有限/非正数、超出精度、余额不足或不安全数值均拒绝。查看与确认转账为本地零 API；普通消息界面不提供“模拟 TA 转入”，AI 只能通过 `terminal_transfer_proposal` 创建 incoming pending，不能直接修改余额或生成已入账事实。

## D75 TTS 语音消息使用独立本地配置与稳定请求 ID
**决定**：设置桌面新增“语音”入口，OpenAI-compatible Speech endpoint、API key、模型、voice、格式和调用状态只保存在 Provider IndexedDB，默认关闭。消息 App 仅在用户显式点击“合成并发送语音”时发起单次 TTS 请求；音频二进制保存到 Assets IndexedDB，v40 消息只保存 `AssetRef`、输入文本、格式、时长和稳定 `voiceRequestId`。

**恢复与边界**：请求开始前持久化联系人、文本和请求 ID；若页面重载时状态仍为 requesting，则明确转为中止错误并提供手动重试。重试复用同一请求 ID，内核在插入前去重，不能重复生成消息或应用任何 ops。查看、播放和读取已有语音均为零 API；本切片不实现麦克风录音、自动 TTS、通话实时语音、音频保活或关系/剧情推进。

## D76 本地通话壳只记录终端通话事实
**决定**：通话入口复用资料桌面已有“通话”图标，第一版只实现呼叫、模拟来电、接听、模拟 TA 接听、拒绝、取消、结束和历史记录。通话对象必须是已接受好友，记录写入 v40 已预留的 `world.terminal.callRecords`，状态限定为 `completed` / `missed` / `cancelled`。

**API 与事实边界**：所有通话查看和状态操作均为本地零 API；不接入 TTS、实时语音、音频保活或麦克风录音。记录以 `callId` 幂等，重复操作不重复写入；通话不推进时间、地点、关系、预约、事件或深度剧情，也不解析 AI 输出。联系人头像和名称只从当前世界状态读取，缺失头像使用 UI 回退占位。

## D77 夜间主动来信使用确定性本地轮换
**决定**：时钟进入 `night` 或 `late-night` 时，系统从已接受好友中按日期确定性轮换一位角色，向其终端线程写入一条主动文本消息；消息使用已有消息结构和联系人上下文，不新增 schema 或页面入口。没有已接受好友时不生成消息。

**幂等与边界**：同一日期、发送者和夜间槽只允许一条主动来信，重复时间事件不会重复插入。该切片不调用 Provider，不自动生成 AI 文本，不改变时间、地点、关系、预约、事件或深度剧情；用户查看消息仍为本地零 API，后续回复生成仍需用户显式点击。

## D78 远程约定采用提议、同意、写入日历三段确认
**决定**：SaveFile 从 v40 升至 v41，在 `world.terminal.appointmentRequests` 保存双方发起的远程约定提议。消息 App 允许玩家发起提议或让 TA 发起提议；玩家发起的提议由本地流程立即视为双方同意，不再要求额外模拟 TA 接受。提议状态与 `world.appointments` 分离，接受只表示双方同意，玩家仍需显式点击“加入日历”。旧存档中仍为 pending 的玩家提议可直接加入日历，并在确认时规范为 accepted。v40→v41 migration 只补空提议数组。

**白名单与边界**：提议和确认都必须校验已接受好友、未来日期、当前日历时段和当前地图地点；最终写入复用 `make_appointment`，稳定 appointment ID 保证重复确认幂等。查看、创建、接受、拒绝、撤回和加入日历全部为本地零 API，不推进关系、时间、地点、事件或深度剧情。AI 叙述不能直接创建提议或预约；未来若允许 AI 提议，也只能进入同一 pending 白名单流程。

## D79 音乐 App 使用应用壳层唯一外链播放器
**决定**：阶段 9 音乐 App 只支持用户维护的 `http(s)` 外链曲目。唯一 `HTMLAudioElement` 挂载在 App 壳层，音乐子页面只操作共享控制器；离开音乐页面、切换日程 / 聊天 / 地图 / 资料 / 设置时不销毁播放器，返回音乐页面恢复当前曲目、进度、音量和播放模式。播放列表与播放现场只保存到 Content IndexedDB，不进入 SaveFile，因此不新增 schema。

**模式与恢复**：顺序、随机、单曲循环为互斥模式；随机队列不会立即重复当前曲目。刷新后恢复列表和位置但不自动播放，只有用户点击播放或切换正在播放的曲目时启动。暂停、切曲、`pagehide` 和节流进度事件保存位置，外链格式、CORS、Range 或加载失败显示可读错误并允许替换/移除。

**平台边界**：不下载、转码、代理或调用网易云 API；网易云扫码、Media Session、离线缓存、本地音频导入、后台/锁屏保证和音频辅助保活另开切片或后续阶段。浏览器切后台或锁屏后的行为遵循平台实际能力，不作持续播放承诺。

## D80 语音缓存与资产管理安排在阶段 10
**决定**：阶段 9 只负责稳定的显式 TTS 生成、请求恢复、重复请求防护和本地音频资产保存。待语音 API 接入与格式处理稳定后，阶段 10 再实现语音资产管理：已生成语音优先从 Assets IndexedDB 播放，不重复调用 API；长按语音消息可选择重新生成，使用新的生成请求 ID，成功后再替换原音频，失败时保留旧音频。

**导出与清理**：阶段 10 提供单条语音 Blob 导出下载、数据管理中的语音缓存统计与清除。清除缓存默认只删除音频二进制并保留文字消息，界面明确标记语音不可用；清除聊天或删除消息时同步回收不再被引用的语音资产。语音资产仍只存 IndexedDB，消息只保存 `AssetRef`，不写入 base64。

## D81 Media Session 安排在阶段 10
**决定**：Media Session 不在阶段 9 外链播放器切片中实现，安排在阶段 10 音乐平台补强，与元数据、系统播放/暂停/上一首/下一首控制和 Android / iOS / PWA 真机验证一起交付。阶段 9 只保证页面仍存活时的应用壳层持续播放，不承诺后台或锁屏持续播放。

**平台边界**：Media Session 只提供浏览器与系统可用的媒体控制和展示接口，不能绕过 iOS / Android 的页面冻结、进程回收或外链网络限制。灵动岛、锁屏卡片和耳机按键是否显示或可用，以具体系统与浏览器实现为准，不能作为跨平台硬承诺。

**主题边界**：名牌颜色通过 CSS 变量控制，未来更换主题或墙纸时可由主题包统一替换，不在聊天组件中硬编码颜色。名牌颜色编辑入口不作为新的系统 UI 入口。

**决定**：阶段 9 的 PWA 切片只负责 standalone 外壳的背景延伸、安全区变量和 `100vh / 100svh / 100dvh` 高度回退，并在 manifest 与 HTML 中预留 192、512、maskable 和 Apple Touch Icon 的 PNG 路径。现有 SVG 保留为回退资源；PNG 文件由用户后续放入 `public/icons/`。

**应用名称**：顶部项目名允许用户点击编辑，名称限制为本地 UI 标题文本并保存到浏览器 localStorage；取消或清空输入不覆盖当前名称，不进入世界存档、不新增 schema、不调用 API，默认名称为“小小地图”。

## D87 桌面图标长按排列与本地持久化

## D88 终端消息整行长按编辑与删除

**资产与引用**：删除消息不会自动删除其贴图或语音 Asset IndexedDB 资源，避免破坏其他消息引用；已有引用在目标消息不存在时继续使用保存的本地预览文本。消息操作菜单保持单一活动状态，不与转账、远程约定等面板同时展开。

## D90 表情包图库与重回请求
**决定**：表情包先导入全局本地图库，点击图库条目后才发送；本地图片二进制保存在 Assets IndexedDB，图库元数据保存在 Content IndexedDB v10，SaveFile 仅保存消息中的 `AssetRef`。删除图库条目不会破坏已有消息引用；仅当本地资产不再被图库或终端消息引用时才回收二进制。外链贴图只保存 `http(s)` URL，不隐式下载。

**重回边界**：重回请求使用现有终端 `system` 消息保存，附加要求允许为空；请求本身不切换面对面场景、不推进关系或剧情，只有用户显式点击“生成回复”时才调用文本 Provider，模型只能生成同意、暂缓或附带条件的自然语言。

## D93 通话页面采用通讯录式紧凑布局
**决定**：终端通话页面复用联系人页面的紧凑单行结构，仅展示已接受好友。每行保留头像、姓名及右侧简介、角色层级与确定性地点，并在最右侧提供“呼叫”和“让TA来电”图标操作；当前通话状态与接听、拒绝、结束等操作也使用紧凑图标按钮。

**通话记录与边界**：通话记录改为头像、姓名、状态和简短日期信息的紧凑列表，默认展开并可折叠。折叠状态保存在 `tokimeki.callHistoryCollapsed.v1` localStorage 偏好中，不进入 SaveFile。所有查看和操作继续为本地零 API，不改变关系、时间、地点、预约、事件、剧情或 schema v41。

## D94 半正式角色 / NPC 转正采用用户确认式入口
**决定**：`promote_npc` 内核 op 已提供半正式 NPC 转为正式角色的确定性能力，但完整用户入口安排在阶段 10 前段单独实现。用户从联系人或角色资料进入转正面板，先查看 NPC 已有事实（名称、facts、tags、轻记忆、头像、住所与日程），再编辑正式角色卡字段；可选的 AI 扩写必须由用户显式触发，结果只作为草稿建议。只有用户最终确认后，才执行 `promote_npc`。

**数据与事实边界**：转正保留稳定 ID、头像、住所、日程和轻记忆，将角色从 `world.npcs` 移至 `world.characters` 并标记 `source: 'promoted'`。转正不自动改变关系轴、时间、地点、预约、事件或剧情，不新增 SaveFile 字段或 schema 版本。AI 不得未经确认直接转正，也不能把转正包装成远程终端行为；转正后的正式角色才进入完整角色卡、面对面聊天和正式角色管理流程。

## D95 阶段 9 采用短时回归后进入阶段 10
**决定**：阶段 9 已完成联系人、消息、转账、TTS、通话、夜间来信、远程约定、外链音乐、终端桌面 UI、PWA 外壳和对应补强切片。各切片已分别通过构建、自动化测试与 diff 检查；最近一次通话 UI 切片全量测试为 353 项通过。进入阶段 10 前只需做一次短时回归，覆盖关键入口、好友/消息/通话本地流程、音乐跨底栏播放现场和 PWA 图标资源，不要求重新进行长时间沉浸式验收，也不把后台音频保活、Media Session 或 iOS 真机限制作为阶段 9 的阻塞条件。

**收尾标准**：短时回归若无阻塞性缺陷，阶段 9 即可视为完成并进入阶段 10；之后发现的非阻塞 UI 问题按独立修正切片处理，不回滚阶段划分。阶段 10 优先处理 NPC 转正用户入口、全局设置/Provider 配置迁移、角色/世界包和语音资产管理。

## D96 阶段 10 首切片采用多配置 OpenAI-compatible Speech Provider
**决定**：阶段 10 首个垂直切片将现有单一 TTS 配置扩展为多个命名语音 API 配置，并在 Provider IndexedDB 中保存一个全局默认语音配置 ID。每份配置包含名称、OpenAI-compatible Speech endpoint、API key、模型、voice、输出格式和可选自定义 headers；请求仍只在用户显式连接测试或后续显式生成时发起。

**兼容与边界**：Provider DB 从 v4 升级到 v5，旧版 `tts` 单例配置自动补默认名称并继续作为默认配置；API key 永不进入 SaveFile 或普通导出包。默认配置或未来角色绑定引用中的语音配置禁止直接删除，必须先切换或解除引用。该切片不修改世界 SaveFile v41，不实现角色绑定、消息语音附件、缓存或 Media Session。

## D97 角色消息语音采用原位附件与显式生成
**决定**：消息 App 仅允许为角色发出的文字消息生成语音；面对面聊天仅允许为 `assistant` 角色台词生成语音，并按 `speakerId` 解析角色语音 Provider。生成入口位于消息长按菜单，每次点击最多发起一次 OpenAI-compatible Speech 请求，全局同时只允许一个语音请求。成功后把音频附件原位写回目标文字消息，不插入重复语音消息；重生成成功后替换旧引用，失败时保留旧音频。

**兼容与边界**：面对面聊天保存在 Content IndexedDB，`ChatMessage` 增加可选稳定 ID 和语音附件；旧记录读取时自动补 ID 并回写。终端消息复用 v41 已有的可选音频资产字段，旧 `type: 'voice'` 消息继续兼容播放，因此世界 SaveFile 保持 v41。编辑文字会清除不再匹配的语音引用，删除或替换后仅回收无其他引用的 Assets IndexedDB 二进制；包含聊天的 zip 导出继续使用 `AssetRef` 和独立音频文件，不写入 base64。统一跨消息缓存、下载和数据管理留给下一垂直切片。

## D98 语音缓存按非密钥配置指纹跨消息复用
**决定**：语音二进制继续保存在 Assets IndexedDB，并以规范化文本、语音配置 ID、endpoint、model、voice、format 和排序后的自定义 headers 计算本地指纹；API key 不进入指纹。首次显式生成会先查本地缓存，命中时直接复用同一 `AssetRef` 且不调用 Provider；已有语音的“重新生成”明确绕过缓存，只有新请求成功后才原位替换旧引用，失败时保留旧音频。

**清理与导出**：数据与隐私页显示语音资产数量、字节数和消息引用数。清理时先移除面对面聊天、当前世界和本地快照中的语音引用，保留文字及“语音不可用”元数据，再删除无引用二进制；若同一资产仍被头像、贴图或其他非语音功能引用，只移除语音缓存标记，不删除文件。单条播放、下载、统计、缓存命中和清理均为纯本地零 API。存档 zip 继续以独立文件保存音频，并携带不含密钥的缓存元数据；SaveFile 保持 v41。

## D99 Media Session 只增强系统控制，不承担后台存活
**决定**：App 壳层唯一音乐播放器在浏览器支持时注册 Media Session，使用当前曲目标题、艺术家和本地 PWA 图标更新系统元数据，并映射播放、暂停、上一首、下一首操作。播放状态与有效进度同步到系统媒体面板；无曲目或切曲加载时清除旧元数据 / 进度。浏览器缺少整个 API、单个 action 或 position state 时分别静默回退，应用内播放器行为不变。

**平台边界**：Media Session 不创建第二个播放器、不增加网络请求、不改变外链播放列表或 Content IndexedDB 数据，也不进入 SaveFile，因此 schema 保持 v41。它不能阻止 iOS / Android 冻结页面、回收进程或中断外链；锁屏、控制中心、耳机按键和灵动岛是否展示由具体系统与浏览器决定。代码侧能力矩阵记录在 `docs/06-media-session-capabilities.md`，Android / iOS 真机结果由用户补充。
## D100 NPC 转正首个用户入口采用纯本地草稿确认
**决定**：联系人页的半正式 NPC 提供“转正”入口。打开面板只读取并展示名称、稳定 ID、facts、tags、轻记忆、头像、住所和日程；角色简介、性格、当前处境、初次完整对话开场和示例台词先形成可编辑本地草稿。只有用户点击最终确认并通过明确确认框后，才提交已注册的 `promote_npc` op。

**边界**：本切片不调用 AI、不改变时间、地点、关系、预约、事件或 SaveFile v41。转正成功后同步创建本地角色库卡片，角色库若已有相同 ID 则阻止操作，避免覆盖用户资料。AI 扩写建议另行作为显式独立切片实现。

## D101 NPC 转正 AI 扩写仅生成可编辑草稿
**决定**：转正面板提供“AI 扩写草稿”按钮。只有用户主动点击时才向当前角色 `narrate_main` Provider 发起一次请求；请求包含 NPC 事实、当前草稿，以及该角色最近的有界面对面对话与终端纯文本/语音转写摘录，要求只返回角色卡字段 JSON。每类摘录最多 12 条、单条最多 320 字；系统消息、旁白、其他角色台词、贴图、转账和二进制不发送。摘录只用于推断口吻、兴趣与互动习惯，不作为时间、地点或经历等世界事实。返回结果只回填面板中的本地草稿，用户仍需检查、编辑并再次确认后才能执行 `promote_npc`。

**边界**：生成失败、格式无效或 Provider 未配置时保留原草稿，不写入 SaveFile、角色库、关系、时间或剧情；AI 输出中的 ops、数值、地点和未提供事实均不被接受。该动作不后台重试、不自动触发，调用频率由用户点击次数决定，每次点击最多一次请求。

## D102 本地存储容量仅做浏览器侧可见性提示
**决定**：数据与隐私页显示浏览器 `navigator.storage.estimate()` 返回的已用空间、配额和占用比例，并显示持久化存储标记。用户可显式请求持久化存储；该请求只作用于当前浏览器，不上传数据、不调用 Provider。

**边界**：容量数字由浏览器统计，可能包含同源或浏览器级其他数据，仅作为参考，不改变 IndexedDB 结构，不升级 SaveFile schema，也不承诺平台一定授予持久化权限。

## D103 资产引用完整性首切片只读审计
**决定**：数据与隐私页提供显式本地完整性检查，扫描当前世界、全部快照、面对面聊天和贴图库中的 `AssetRef`，并与 Assets IndexedDB 的实际记录比对。报告显示引用总数、被引用资产数、本地资产数、缺失或零字节资产及无引用孤立资产，并列出失效引用来源路径。

**边界**：检查过程纯本地、零 API、零写入，不自动移除引用或删除孤立资产。修复和回收必须在审计结果稳定后另开独立切片，并继续执行引用检查与明确用户确认。SaveFile 保持 v41。

## D104 角色包先于世界包实现并隔离世界专属事实
**决定**：阶段 10 的资料包首切片实现角色包。角色包使用独立 `manifest.type = character` 与包 schema v1，携带可复用角色卡字段、头像/立绘引用、初始关系轴、礼物偏好和世界书引用；导出提供“含本地图片 / 仅保留引用”选择。导入提供“仅加入角色库 / 同时加入当前世界”两种明确目标。

**边界**：角色包不携带当前世界住所、日程、关系记忆或 API 配置。加入世界时由现有 `addCharacterToWorld` 以当前地点建立该世界自己的住所与空日程；内嵌图片写入 Assets IndexedDB 并改用新的本地资产 ID，引用型图片缺失时保留角色卡并显示可修复提示。覆盖同 ID 角色库卡片或加入已有同 ID 世界角色前必须明确确认/拒绝，不升级 SaveFile v41。

## D105 TXT 资料导入采用全文单字段映射

**边界**：TXT 导入纯本地、零 API，不解析图片、不覆盖现有条目 ID，不改变 SaveFile。DOCX 导入另开切片，仅提取纯文本。

## D106 世界包只合并静态内容并保留玩家进度
**决定**：资料页提供世界包导入导出。世界包使用 `manifest.type = world` 与包 schema v1，包含可复用地图几何、角色/NPC 与模板、物品定义、事件定义、世界书和角色卡；导出前重置节点探索状态、访问次数和节点记忆。图片支持“含本地图片 / 仅保留引用”。导入采用显式“合并到当前世界”，同 ID 静态内容覆盖前要求确认。

**边界**：世界包不包含玩家时间、位置、行动消耗、库存、关系、终端、预约、事件历史、快照或 Provider/API key。内嵌资产写入 Assets IndexedDB 并改用新的本地 ID；导入失败回收本次新写入资产，当前世界保持不变。SaveFile 继续保持 v41。

## D107 图像生成使用独立入口与显式能力声明
**决定**：阶段 10 的图像生成从用户可见的任务路由列表移到设置桌面的独立“图像”入口。内部继续保留 `image` TaskId 与 Provider 绑定以兼容现有路由；图像页只选择 OpenAI-compatible Provider，并在 Provider IndexedDB 中保存尺寸、质量、style、响应格式、参考图能力、可选 edits 端点和请求状态。

**请求与降级边界**：纯文字生成使用 `/images/generations` JSON；只有用户明确把当前 Provider 标记为支持参考图、并且后续确有本地参考资产时，才使用 `/images/edits` multipart。未声明能力时不得发送参考图，后续锁脸功能必须明确显示已降级为固定外貌提示词。保存、查看和切换均为零 API；连接测试和生成图像分别由用户显式点击，每次最多一次请求。图像设置不进入 SaveFile，世界 schema 保持 v41。

## D108 角色图像提示词与生成结果按世界隔离

## D109 锁脸参考图按世界与身份隔离
**决定**：角色锁脸按 `saveId + characterId` 保存，用户锁脸按 `saveId + player/persona` 保存；外貌描述和参考图 `AssetRef` 位于 Provider IndexedDB，图片二进制位于 Assets IndexedDB，均不写入 SaveFile v41。角色生成只有在用户启用锁脸、参考图存在且当前 Provider 明确启用 OpenAI-compatible `images/edits` 时才发送参考图；否则明确降级为固定外貌提示词。用户锁脸首版仅管理本地参考，不自动生成或替换玩家头像。

## D110 图像本地配置进入全局备份并采用保守清理
**决定**：全局备份升级为 v2，新增图像生成设置、角色视觉配置和用户视觉配置；导入继续兼容 v1，缺失字段迁移为空配置。设置迁移包升级为 v2并携带非敏感图像选项，请求统计与最近错误不迁移，普通导出继续排除 API key 和鉴权 headers。相关图片二进制沿用 Assets IndexedDB 与全局备份资产目录，不写入 JSON base64。

**清理边界**：数据与隐私页按图片 MIME 统计数量与字节数，并单独统计角色视觉和锁脸引用。清理只删除完整引用扫描确认无人使用的图片；头像、立绘、地图、贴图、快照或任一锁脸配置仍在引用时必须保留。锁脸引用已失效时先移除引用并关闭锁脸。所有统计、审计与清理均为纯本地操作，SaveFile 保持 v41。

## D111 Tauri 桌面版先建立最小权限构建骨架
**决定**：桌面版采用 Tauri 2，复用现有 React/Vite 静态产物、IndexedDB 数据边界和 PWA 图标。首个切片只建立可复现的桌面工程、开发/构建命令、窗口与 CSP 配置；默认 capability 仅包含 `core:default`，不开放文件系统、Shell、通知或原生网络权限。Tauri CLI 与 Rust 主依赖使用精确版本，首次具备 Rust 工具链并成功构建后补交 `Cargo.lock`。

**CORS 与验证边界**：普通 Tauri WebView 中的浏览器 `fetch` 不等于原生 HTTP，也不能宣称自动绕过 Provider CORS。后续必须通过独立传输层接入受权限约束的 Tauri HTTP 插件，且只允许请求用户显式配置的端点；网页版继续使用浏览器 `fetch`。当前开发机没有 Rust/Cargo，因此本切片只验证前端构建、配置、CLI 与自动测试，不宣称原生安装包已构建或运行。SaveFile 保持 v41。

## D112 移动端能力诊断区分 API、接入状态与可靠性
**决定**：数据与隐私页纯本地显示当前平台族、浏览器/standalone 形态、通知权限、Service Worker 是否受控、Media Session、持久化存储及后台相关 API 可见性。诊断不申请权限、不注册 Service Worker、不调用 Provider，也不根据 User-Agent 宣称具体系统版本必然支持某项能力。

**平台边界**：API 存在只表示浏览器暴露接口，不代表 Android/iOS 会允许后台请求、通知、媒体控制或同步任务持续运行。当前没有 Service Worker 和通知入口；后台可靠降级继续采用页面隐藏前落盘、返回前台识别中断、用户显式重试和防止重复 ops。真机结果按设备、系统、浏览器与安装形态记录，不能泛化为跨平台承诺。SaveFile 保持 v41。

## D113 不使用 Service Worker 代理 Provider 请求
**决定**：不实现 Service Worker 单次生成请求代理、流式片段后台写入或 Background Sync 自动重放。Service Worker 跨域请求仍受 CORS 限制，移动系统可随时终止 Worker；自动重放还可能导致重复计费、重复文本和竞态。为恢复请求而保存 endpoint、鉴权 headers、API key 与完整 prompt 也会扩大敏感数据暴露面。

**恢复边界**：继续采用前台直接请求、请求前保存 recovery、流式正文落盘、页面隐藏时标记中断、回到前台后由用户显式重试，以及 requestId / `opsApplied` 防重复应用。Service Worker 后续只可分别用于版本化静态壳或通知展示，不得读取 Provider 配置、持有 API key、发起生成或自动重试。SaveFile 保持 v41。

## D114 移动端通知只做显式启用的本地完成提醒
**决定**：数据与隐私页提供完成通知开关和测试按钮。只有用户点击启用时才请求权限并注册最小通知 Worker；面对面回复或终端回复完成且页面处于后台时，尽力显示固定通用文案。页面前台不通知，通知不包含角色名、台词、prompt、世界名或 API 信息。

**平台与网络边界**：Worker 只处理通知点击，不注册 fetch、push、sync 或 periodic sync，不访问 IndexedDB，不持有 Provider 配置或 API key。系统冻结页面时完成回调可能不执行，因此不承诺产生通知；没有远程推送、定时唤醒、夜间来信后台提醒或自动生成。启用、测试和显示均不调用 Provider，设置保存在本机 localStorage，SaveFile 保持 v41。

## D115 本地音乐使用 Content 引用与 Assets 二进制分离
**决定**：音乐曲目兼容原有 http(s) URL，并可改为保存本地 `stored AssetRef`；用户显式导入的音频 Blob 只写入 Assets IndexedDB，分类为 `music`，曲目与播放现场继续保存在 Content IndexedDB。导入、播放、编辑和删除均不上传文件、不调用 Provider，也不写入世界 SaveFile，因此 SaveFile 保持 v41。

**回收与兼容边界**：删除本地曲目时，仅在没有其他音乐曲目引用同一资产且资产分类确为 `music` 时回收二进制。通用资产完整性审计把 MusicState 纳入引用根；全局备份 v4 可携带音乐曲目、二进制及 `music` 元数据，旧备份继续可读。支持 MP3、M4A、AAC、OGG、WAV、WebM 与 FLAC 文件选择，但实际解码能力仍由浏览器和系统决定。外链曲目的显式离线缓存、占用统计与批量清理放在下一垂直切片。

## D116 外链音乐只在显式操作时下载并保留 URL 回退
**决定**：外链曲目只有在用户点击“缓存离线”时才执行一次 CORS GET，且请求使用 `credentials: omit`、不附加 Provider headers 或 API key、不后台重试。下载成功后曲目同时保留原 http(s) URL 和本地 `AssetRef`，播放器优先读取本地资产；缓存缺失或读取失败时回退原 URL。下载失败、HTTP 错误、空响应或明显的 HTML/JSON 响应均不改变曲目。

**清理边界**：单曲“移除缓存”和数据管理批量清理只移除同时具有 URL 的缓存引用，曲目继续使用原 URL；只有没有 URL 的本地导入视为用户原始内容，不进入批量缓存清理。数据管理分别统计本地导入、外链缓存、引用与孤立音乐资产；孤立清理只删除完整引用检查确认无人使用且分类为 `music` 的二进制。所有统计和清理均零网络、零 Provider API，SaveFile 保持 v41。

## D117 世界包与事件包教程采用就地内置帮助
**决定**：世界包和事件包的导入/导出页面使用问号小图标打开内置教程，不把仓库 Markdown 作为普通用户必须另行寻找的唯一说明。世界包教程说明可复用静态内容与世界存档进度的区别、推荐制作流程、图片打包、ID 冲突、zip 结构和发布检查；事件包教程说明当前手工模板流程、最小示例、触发字段、权重/冷却/关系阶段/张力限制，以及事件总是不触发时的逐步降级排查。

**边界**：教程明确披露当前尚无完整可视化事件编辑器，导入只安装定义而不立即触发；事件 ops 仍经过内核白名单校验。打开、阅读和关闭教程均为纯本地 UI，不读取文件、不修改数据、不调用 Provider，也不改变 SaveFile v41 或资料包 schema。

**边界**：模板下载不读取当前世界、不修改数据、不访问网络、不调用 Provider，不包含 API key、Provider 配置、用户存档或 base64 资产；世界存档继续保持 v41，世界包 schema 继续为 v1，事件包继续使用当前导入 schema。

## D124 创意工坊首切片只安装声明式包并按世界绑定
**决定**：创意工坊包 v1 只允许严格 schema 校验的 `manifest.json`、`app.json`、`rules.json`、可选事件/Prompt/资产元数据及本地图片。禁止 JavaScript、TypeScript、React、HTML、CSS、脚本 URL、base64 和任意网络能力。导入时从声明内容反向推导权限，缺少声明、断裂引用、不安全表达式、未开放 op 或未知文件均阻止安装；额外权限显示警告。

**决定**：当前世界已启用的工坊包可在终端桌面显示动态图标，并由固定 React 组件解释声明式页面。运行时只执行包内导航和 `set-local`，并允许组件读取 manifest 逐项声明的世界事实；每次执行前重新检查权限和引用。`submit-op`、`trigger-event`、规则、Prompt 与 Provider 动作保持禁用，不接入核心循环或网络。

## D127 AI 工坊草稿只允许单次显式调用并先进入本地编辑器

## D128 工坊活动首切片只组合受限确定性效果

## D129 工坊制作流程演进为用户 API 驱动的多轮 Agent
**关系**：本决策扩展 D127。D127 的单次、受限草稿生成仍作为新建工程入口；进入编辑器后改为用户每轮显式触发的 Agent 修改。

**决定**：保留 `workshop_draft` 路由以兼容现有 Provider 配置，但产品语义升级为“工坊 Agent”。初稿进入编辑器后，用户可继续发送自然语言指令；每轮向用户配置的 API 发送当前工程源码、最近对话和本地校验诊断，要求返回说明与完整 workshop v1 工程。返回内容必须通过严格 schema，然后回到同一编辑器继续校验和预览；支持撤销上一次 Agent 修改，不自动安装或写世界状态。

**成本与数据边界**：当前每次用户发送最多调用一次 API，不自动修复、不自动重试、不后台运行。请求不携带 SaveFile、已安装包、API key 本体或世界游玩状态；API key 仅按既有 Provider 机制用于用户端点鉴权。对话和草稿仍只存在当前页面，SaveFile 保持 v41，Content IndexedDB 保持 v12。真正的工具调用协议、局部 patch、可配步数/费用预算和自动修复循环必须作为后续独立切片。

## D130 工坊 Agent v1 使用 Provider 无关的严格工具协议

**决定**：工坊 Agent 响应升级为版本化应用层 JSON 工具协议，不直接依赖任一厂商的原生 function calling。v1 响应包含 `protocolVersion: 1`、给用户的简短说明和恰好一个工具调用；当前唯一工具为 `project.replace`，参数是完整 workshop v1 工程。调用 ID、工具名、参数、协议版本和完整工程均经严格 schema 校验，未知工具、多工具调用、额外字段与非法工程全部拒绝。旧的 `{ message, package }` 和裸包响应暂时保留为迁移兼容输入，但新请求明确要求工具协议。

**执行与成本边界**：`project.replace` 只生成待替换的内存编辑器草稿，结果仍走现有本地校验与预览；它不能安装包、写 SaveFile、修改世界事实、读取额外资料或发起网络请求。每条用户指令仍最多一次 API 请求，没有后续工具回传或自动循环。能力目录随后由 D131 补充，局部 patch 由 D132 补充；本地校验/预览工具、步骤预算与自动修复仍分别作为后续切片。SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D131 工坊 Agent 能力目录在请求前纯本地查询

**决定**：新增版本化只读 `capabilities.list` 目录，由当前工坊包版本、运行时版本和 schema 常量构造。目录明确区分已启用 UI 动作、带条件的活动调度、当前禁用动作、可读取世界资源、活动 hook/效果、仅可声明但尚不运行的 events/prompts/Provider、资产限制与禁止项。Agent 系统提示不再自行维护组件、hook 和效果列表，而以请求中的 `capabilityQuery.result` 为权威来源。

**调用与数据边界**：每次用户发送 Agent 指令前，本地同步查询一次目录，并合并到原有单次 Provider 请求；不产生额外 API、自动第二轮或后台调用。目录只含产品协议常量，不读取 SaveFile、已安装包、IndexedDB、Provider 配置、端点或密钥，也不执行任何写操作。局部 patch 随后由 D132 补充；校验/预览工具和自动多步循环仍是后续独立切片。SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D132 工坊 Agent 局部 patch 在副本上原子执行

**决定**：Agent v1 新增 `project.patch`，与 `project.replace` 二选一且每轮仍只允许一个工具调用。patch 采用受限 JSON Pointer，只开放 `add`、`replace`、`remove`，单次最多 100 项；路径必须位于 `manifest`、`app`、`rules`、`events`、`prompts`、`assetMeta` 六个工程根下。禁止空路径段、无效转义、数组越界以及 `__proto__` / `prototype` / `constructor` 路径，`move`、`copy`、`test` 和任意脚本不属于协议。

**原子性与降级**：本地先复制当前 JSON 工程，再按顺序应用全部操作；任一操作失败或最终结果未通过 `WorkshopPackageSchema`，整组结果都不进入编辑器。当前源码不是有效 JSON、需要整体重构或无法安全定位时，Agent 必须退回 `project.replace`。成功 patch 与完整替换共用编辑器撤销、校验和预览流程，不自动安装或写世界状态。patch 只减少单次响应体，不增加 API 次数；SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D133 工坊 Agent 请求前生成只读校验与预览摘要

**决定**：新增版本化本地 `project.inspect`，复用编辑器同一份分析结果，不重复建立第二套校验器。结果区分 JSON 语法、包 schema、完整校验、预览可用性和导出状态；携带最多 100 条诊断、最多 200 项所需权限，并提供包 ID/名称/版本、入口页、页面标题、组件/动作计数、规则 hook 与 events/prompts/assets 数量。预览摘要不包含组件正文、表单值或渲染后的世界事实。

**隐私与调用边界**：`package-id-conflict` 在构造 inspection 时过滤，避免向 Provider 暴露本机已安装包 ID；其他权限、引用和资产载荷诊断继续保留。每次用户发送前，本地同步生成一次 inspection，与当前源码、历史和能力目录合并进原有单次 API 请求；不额外调用 Provider，不渲染页面，不读取 SaveFile 世界事实值，不发送资产二进制，也不写入任何状态。自动读取修改后结果、再次调用模型和修复循环仍须等待步骤/费用预算切片；SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D134 工坊 Agent 预算由 Provider 执行层强制

**决定**：编辑器内的工坊 Agent 提供仅在当前页面生效的最大步骤数、最大 API 请求数、单次输出 token、总输出 token 和上下文安全余量。每次请求前使用项目既有近似 token 算法计算完整 system/user 消息；可用输入为 `contextWindow - 本次输出上限 - safetyMargin`。若步骤、请求、总输出或输入上下文超限，执行层在联网前拒绝；实际发送给适配器的 `maxOutputTokens` 取 Provider 配置、单次预算和剩余总预算三者中的最小值，返回超出该限制的结果也不进入编辑器。

**调用与费用边界**：当前 Agent 指令仍只执行 1 步并最多调用 1 次 API，初稿生成入口仍沿用原有单次 Provider 限制；较大的步骤/请求上限只为下一切片的有界自动修复循环提供执行契约，不代表本切片会自动追加请求。页面只报告近似输入/输出 token 和请求次数，不虚构不同端点、模型或渠道的货币价格。预算、用量和 Agent 对话都不持久化，不写 SaveFile 或 IndexedDB；SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D135 工坊 Agent 只对本地拒绝结果执行有界自动修复

**关系**：本决策在 D134 的预算执行契约上开放多步；D134 记录的是预算切片完成时的单步状态。

**决定**：用户每次显式发送指令后先执行 1 次 Provider 请求。仅当返回内容无法解析为 JSON、违反 Agent 工具协议、patch 无法原子应用、最终工程未通过 schema，或工程存在权限、引用、条件等正式包校验错误时，才把本地错误及上一步输出的有界摘录加入下一步请求。中间失败结果不会进入编辑器；首个完整通过的工程才替换内存草稿。达到最大步骤、最大请求或总输出 token 任一上限即停止并保留原草稿。把任一上限设为 1 可关闭追加请求。

**上下文与调用边界**：每步仍最多 1 次 API，整个用户动作最多调用 `min(maxSteps, maxRequests)` 次且顺序执行，不对网络错误、HTTP 错误、取消、空响应或预算错误重试。联网前纯本地无损压缩有效工程 JSON；空间仍不足时依次移除最旧对话、截短失败输出摘录，并可省略部分 inspection 诊断正文但保留总数/分级计数。完整工程绝不做有损截断，仍超限则停止。修复请求不读取 SaveFile、世界事实值、已安装包或二进制；初稿生成入口仍是单次调用。SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D136 工坊 UI 绑定只读取本地标量与授权世界快照

**决定**：workshop 包 v1 在不提升包版本的前提下新增可选统一绑定对象。标题、正文、卡片、列表、按钮/确认文案和进度可从包内本地状态或 `world.read` 安全快照取显示值；静态字段继续作为回退。绑定只支持最多 8 段的安全路径数组、固定格式枚举、前后缀和标量 fallback，不接受模板表达式、任意 JSONPath、函数或代码。安装校验从绑定反向推导 `app.local-state` 或具体 `world.read:<resource>`，运行时再次复核权限。

**状态与安全边界**：世界资源先转换成固定展示快照，不能沿路径进入完整 SaveFile；列表和文本均有限长，危险原型字段被 schema 与运行时双重拒绝。绑定只能替换显示内容，不能改变 action、op payload、规则、权限或世界事实。输入/选择器继续只写按 `saveId + packageId` 隔离的本地标量，因此可以形成“用户输入 → 本地状态 → 多组件展示”的零 API 闭环。能力目录升级到 v2并向 Agent 提供绑定目标和精确语法；包 schema/runtime 仍为 v1，SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D137 工坊活动成本先聚合检查并与结果原子提交

**决定**：活动规则新增通用 `stat` / `item` 成本和可选成功/失败展示文案。stats 成本只指定 `player|world`、通用键、正数 amount 与扣除后下限；同目标同键先聚合再检查。物品成本按物品 ID 聚合并检查当前库存。通过预检后，成本被转换成正式 `add_stat` / `take_item`，与既有效果一起在同一个世界副本上按 op schema、限幅和权限执行；任一项失败则成本、奖励和一次性/冷却状态全部不写回。

**交互与扩展边界**：活动成本不包含时间或行动点，继续遵守“相遇与对话不收费”；更多钩子留在下一切片。成功文案只在内核确认整组提交后显示，失败文案必须附带内核拒绝原因，均不能充当状态事实或覆盖校验。能力目录升级到 v3并公开精确成本/结果语法。本切片纯本地、零 API，不新增业务数值字段；包 schema/runtime 仍为 v1，SaveFile 保持 v41，Content IndexedDB 保持 v12。

## D138 工坊自动活动只扩展到具备确定性世界上下文的现有钩子

## D139 工坊事件先开放用户显式触发的原子本地闭环

**决定**：当前世界启用工坊包后，把通过完整包校验和当前世界引用检查的 `events.json` 定义同步进 `world.eventDefs`，并用包 ID 标记来源。包内 `trigger-event` 按钮只有在事件属于同包且逐项声明 `event.install` / `event.trigger` 时可用。触发继续复用正式事件条件、地点、时段、在场角色、关系阶段、once、cooldown、历史与 choice 机制；事件本体和 choice 的每个结果 op 还必须具有 `op.submit` 权限，并在世界副本上完整成功后才原子写回。

**生命周期与调用边界**：工坊事件安装副本固定 `weight: 0`，不进入导演随机池；本切片只允许用户显式按钮触发。停用包会移除其事件定义和待触发排程，但保留已经形成的事件历史与其他已提交世界事实。事件 ID 与世界原有事件或其他启用包冲突时不覆盖；断裂地点、时段、角色、关系阶段或证物引用不安装。事件效果只开放能力目录列出的原子安全 op；`advance_time`、`move_player`、`move_npc`、`queue_event` 和内部 `run_workshop_activity` 不开放，避免在候选事务完成前广播钩子或留下跨事件排程。纯 prompt 事件不调用 Provider，并明确拒绝到后续 Prompt 切片。整个流程纯本地、零 API；不修改事件核心循环，不升级包 schema/runtime、SaveFile v41 或 Content IndexedDB v12。能力目录升级到 v5。

## D140 工坊 Prompt block 只进入已有生成请求并受双层预算

**决定**：已启用包的 `prompts.json` 通过正式 PromptAssembler 注册，运行时 ID 固定命名空间为 `workshop:<packageId>:<blockId>`，不能覆盖内置块或其他包。当前只开放确实经过该组装器的 `narrate_main` 与 `topic_tree`；旧 v1 数据结构仍可读取，但声明其他任务会在完整包校验中得到明确错误，避免安装数据静默丢失。每次注册都会重新执行记录 schema、完整权限、引用、条件与包预算校验。

**条件、预算与调用边界**：block 文本为静态字符串，不执行模板替换。`when` 只接收日期、时段、地点、世界/玩家 stats 与 flags，以及关系阶段/轴的安全副本；异常或缺失事实只跳过该块。单块文本在进入全局 PromptAssembler 预算前先限制到自身 `tokenBudget`，同包预算总和不得超过 4096 或 manifest 声明的 `prompt.register.maxTokens` 合计。注册、停用和本地查看均为零 API；块只随用户原本触发的叙事或话题树请求进入同一次 Provider 调用，不改变 Provider、端点、输出 token、请求次数或世界状态。停用包立即注销。Provider 用户按钮仍留给下一切片。包 schema/runtime 保持 v1，SaveFile 保持 v41，Content IndexedDB 保持 v12；能力目录升级到 v6。

## D141 工坊 Provider 文本动作只由用户点击并返回本地展示文本

**决定**：开放声明式 `provider-text` 按钮。动作必须引用同包 Prompt，并让 `taskId` 同时通过 Prompt task、`prompt.register` 与 `provider.explicit-text` 三重匹配；可选 `inputKey` / `resultKey` 只访问按世界和包隔离的本地标量状态。非 PromptAssembler 任务只有被同包显式动作引用时才允许保留，避免“可安装但既不自动注册也不能调用”的死配置。每次运行前重新执行完整包校验和权限复核。

**数据、状态与调用边界**：每次用户点击最多调用一次现有任务路由选中的用户 Provider，不后台执行、不自动重试；联网前以完整消息和 Provider 上下文窗口预检。请求只包含固定的“展示文本不具备状态权威”契约、受单块预算限制的静态 Prompt，以及可选的单个本地输入值；不发送完整 SaveFile、聊天、其他包状态、二进制或密钥。返回内容不经过 ops 解析，即使含 `<ops>` 也只是普通文本；最多 10000 字符用于当前页面展示，写入 `resultKey` 时只保留本地状态允许的前 2000 字符。它不能修改世界事实、增加时间或行动点消耗。包 schema/runtime 保持 v1，SaveFile 保持 v41，Content IndexedDB 保持 v12；能力目录升级到 v7。

## D142 同 ID 工坊包只允许显式、安全的严格版本升级

**决定**：ZIP 导入和编辑器草稿都可更新同 ID 已安装包，但新版本必须是严格更高的 `x.y.z`；三段按任意精度非负整数比较，同版本与降级均在写入前拒绝。确认框显示旧版到新版、受影响/已启用世界数、新增与移除权限，以及作者或显示名称变化。新包仍须通过完整 schema、引用和权限校验，更新不会自动安装新 ID，也不会改变任一世界的启用状态。

**原子性与资源边界**：Assets 与 Content 是两个独立 IndexedDB，不能伪装为跨库事务。更新先以全新资产 ID 写入新版二进制，最后在 Content 单表事务中核对预期旧版本并原子替换包记录；替换失败会补偿删除本轮新资产，旧包记录、世界绑定和本地 App 状态不变。成功后保留旧资产，不在缺少完整引用证明时自动删除用户资源。`installedAt` 保留、`updatedAt` 更新；整个流程纯本地、零 API，不升级包 schema/runtime、SaveFile v41 或 Content IndexedDB v12。版本依赖与卸载保护继续作为下一独立切片。

## D143 工坊依赖使用显式版本区间并保护完整生命周期

**决定**：workshop v1 的 manifest 新增可选 `dependencies`，每包最多 50 项；每项使用稳定包 ID、可选的包含式 `minVersion` 和排除式 `maxVersionExclusive`，三段版本继续按任意精度整数比较。重复依赖、自依赖、空区间、缺包、版本不兼容和可达依赖环均拒绝。安装与更新不自动下载、安装或升级依赖；工坊预览和编辑器只在本地显示解析结果，能力目录升级到 v8 让 Agent 可以生成同一声明语法，但不会向 Provider 发送本机已安装包或绑定。

**世界与卸载边界**：安装并启用新包时，其全部依赖链必须已在当前世界启用；更新已在多个世界启用的包时，新依赖必须在每个相关世界启用。启用包会重新检查依赖；停用依赖包前必须先停用当前世界的直接依赖方。只要仍有任何已安装包声明依赖，全局卸载即被阻止，不因依赖方当前停用而绕过。更新依赖包时也不得越过任何已安装依赖方的版本上限。所有生命周期写入在 Content IndexedDB 事务内再次复核，防止仅靠 UI 预检；运行时加载还会按拓扑关系失败关闭不完整或成环的启用集合。流程纯本地、零 API，不修改 SaveFile v41、Content DB v12 或世界事实，包 schema/runtime 仍为 v1。

## D144 工坊数据进入全局备份 v5 并提供只读完整性审计

**决定**：全局备份升级为 v5，在既有全部 Assets 二进制之外，完整保存工坊包记录、按世界绑定和本地 App 状态。导入 v1–v4 备份时，缺失的三类工坊字段迁移为空数组；不修改 SaveFile schema。导入预览会核对包记录 ID、完整包校验、资产声明与映射、ZIP 中实际二进制、依赖版本与环、世界绑定及本地状态复合 ID，并显示包、绑定、状态和提示数量。

**保留与拒绝边界**：审计只读，不自动修复、禁用、覆盖或删除记录。缺失资产、断裂绑定、依赖错误等问题仍允许用户在明确警告后按原样恢复，运行时继续对不可用包失败关闭；卸载后保留的本地 App 状态只计数，不视为损坏。唯有包、绑定或状态出现重复主键时拒绝导入，因为 IndexedDB 写入会覆盖同键记录并造成不可逆的静默丢失。设置页复用同一审计器检查当前浏览器数据；全部流程纯本地、零 API，SaveFile 保持 v41，Content DB 保持 v12。

## D145 工坊收尾采用临时验收工程而非内置官方示例

**决定**：创意工坊不随产品发布固定官方示例包。代码侧使用只存在于 Vitest 的临时依赖包和 Agent 工程，配合精确锁定的 devDependency `fake-indexeddb@6.2.5`，在 Node 中运行真实 Dexie Content/Assets 数据库，贯通 Mock Agent 创建、ZIP 安装、依赖启用、确定性活动、事件、显式 Provider 文本、局部 patch 更新、状态保留、分享导出、卸载、重新导入、完整性审计和全局备份。临时工程不进入生产包、用户数据库或内置模板，也不调用真实 API。

**验收修正**：全流程验收确认运行时必须返回依赖项先于依赖方的拓扑顺序，不能恢复为 IndexedDB 主键顺序；已安装包导出在交给 JSZip 前统一把 Blob 显式读取为 `Uint8Array`，保证浏览器与 Node 验收路径一致。代码侧完成不等于替代真实模型和设备体验；用户自己的 Provider 输出质量、端点兼容性和实际交互仍通过用户显式手测验证。流程不升级包 schema/runtime、SaveFile v41、Content DB v12 或 Assets DB v3。

## D146 StoryScene 时间地点改为自由叙事信息

**决定**：多人剧情的新建与草案编辑界面不再要求地点、开始日期或开始时段。用户可直接在详细大纲中描述任意时间地点；内置预设不再自动引用当前地图节点。`StoryScene.nodeId`、`startDay`、`startSlotId` 在 SaveFile v42 中改为可选历史字段。

**状态与兼容边界**：大纲中的时间地点只是叙事文本，不改变世界时钟、玩家位置、日程、事件坐标或其他事实。参与者、阶段、条件、阅读进度与生命周期继续由内核校验。v41→v42 migration 保留旧剧情已有坐标，不静默丢失数据；本切片纯本地、零 API。
