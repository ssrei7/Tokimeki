# 项目定位

> 新加入的人（或新 agent）从这份开始读。这是摘要，细节在 01–04。

## 一句话

一个纯前端、用户自带 API 的开放世界乙女向 AI 叙事游戏：不是打开就聊，而是走到地图上去生活、去相遇。

## 与其他 AI 聊天产品的区别

市面上的产品几乎都在模拟一个虚拟聊天窗口——打开即对话。本项目的核心动作是**走出去**：

- **地图是核心**，所有功能都与地图联动。世界书绑在地点上，事件坐标是（地点，天，时段），玩家的工作和店铺也是地图上的一个点。
- **空间感**：周三下午去码头能遇到他，因为他周三下午总在那。位置和时间是真的，由代码持有。
- **生活感**：以"天"为单位推进，每天早上有报纸给方向，每晚结算写日记。可以打工、开店、当无业游民。
- **偶遇与动线**是最独特的部分，同时也是最便宜的部分（纯代码查询，不调 API）。这是个好信号。

明确的机制约束：**终端（手机）只能维持关系，不能推进关系**。深度剧情必须到场触发。这条规则用机制保证"走出去"的立意不被聊天窗架空。

## 核心循环

```
晨报（一次合并调用：报纸 + 天气 + NPC 动向）
   ↓
选择行动（消耗时段）
   ↓
移动 → 相遇 → 话题 / 剧情 / 礼物
   ↓
夜间结算 + 日记 + 自动快照
   ↓
睡觉，进入下一天
```

固定的仪式，每天不同的内容。这个仪式感是"在生活"和"在用聊天软件"的分界。

## 界面基线：手机竖屏与地图 App 风格

- 采用 mobile-first 的竖屏布局，优先适配约 360–430 CSS px 宽度；宽屏仅做响应式扩展，不改变核心信息架构。
- 地图是默认首页与视觉锚点：主要操作从地图节点、地点卡片和底部导航进入，聊天、晨报、日记与设置都作为地图 App 的页面或抽屉呈现。
- 使用地图应用常见的层级：顶部状态栏/搜索入口、地图主体、可上拉的地点或事件卡片、底部标签栏；避免把产品做成打开即聊天的单一对话窗口。
- 所有主要触控目标至少 44 CSS px，支持单手操作、窄屏滚动与安全区；信息密度优先保证可读性，不依赖悬停交互。
- 支持浏览器“添加到主屏幕”后的 standalone 全屏体验，隐藏地址栏与浏览器工具栏，保留刘海/圆角屏安全区处理；普通标签页访问仍可用。
- 阶段 4 之前不做装饰性美化，只实现清晰的结构、CSS 变量和组件插槽；即使在朴素样式下也必须保持地图 App 的布局骨架。

## 五条不可动摇的设计支柱

1. **确定性内核 + AI 只写文字**。代码持有一切事实（时间、位置、数值、日程、关系）；AI 输出叙述文字和受校验的 ops 提议。这是长期防止状态漂移的唯一可靠手段。
2. **天数制**。游戏时间与现实脱钩，以天推进。它顺手解决了记忆压缩（日记是天然切点）、存档（每日快照）、事件排程（日历可埋伏笔）三个难题。
3. **默认不调 API**。移动、看地图、翻手机、点已生成的话题全部零延迟零成本。每日 API 调用量与玩家互动次数成正比，与 NPC 数量无关。
4. **一切泛化**。数值走通用 `stats`，布尔走 `flags`，条件走安全表达式。用户能自己定义系统规则，新玩法只通过 op 注册表 / 事件钩子 / prompt block / 数据包四条路接入。
5. **约束创造生活感**。绝对自由会产出空虚。要先有班可翘，才有"翘班去见他"。

## 用户自由度

用户自带 API（项目不提供推理服务），可为不同任务绑定不同 provider。可自建或导入角色、世界书、预设、世界包；事件定义包主要服务于内置内容与未来创作工具，普通游玩不依赖外部事件导入。已亲历的事件可导出为独立可阅读档案。可注入自定义 CSS 美化——界面的审美权交给用户和社区。

也可以只创造一个世界观，与未知角色相遇；遇到喜欢的随机 NPC 可以"转正"为正式角色，然后加联系方式、搬到他家附近、进入他所在的组织——一切看用户的选择。

## 技术约束

纯静态站点，无后端、无账号、无云端。数据全部在 IndexedDB，API key 只存本地且不进导出文件。栈：React + TypeScript + Vite / Zustand / Dexie / zod / expr-eval / Tailwind + CSS 变量 / JSZip / SVG 地图。后期出 Tauri 桌面版（顺带解决 CORS 与存储配额）。

已知摩擦：浏览器直连部分厂商 API 有 CORS 限制。对策是通用适配器 + 连接测试错误诊断 + 桌面版。

## 明确不做

瓦片地图与行走动画、真实时间感知、逐 tick 的 NPC 模拟、NPC 之间真实的幕后对话、完整经济模拟、云同步与联机、多表情立绘系统。每一条都有否决理由，见 `04-decisions.md`——**提出这些方案前请先读那份文档**。

## 三个最大风险

1. **一致性漂移**（玩到第 50 天角色记错事、性格变形）→ 靠支柱 1 + 分层记忆压缩
2. **成本与延迟**（点一下等五秒扣一次钱，探索欲会死）→ 靠支柱 3
3. **范围膨胀**（作者自称"总是突然灵光一闪"）→ 靠 `docs/ideas.md` 想法收纳箱 + 阶段纪律

真正的成本不在写代码：代码约 3 成，prompt 工程约 4 成，调参与体验打磨约 3 成。调试面板是迭代速度的决定性因素，阶段 0 就要做齐。

## 词汇表

| 词 | 含义 |
|---|---|
| 时段 slot | 世界时钟单位，一天 3–6 个，行动消耗它 |
| ops | AI 提议的状态变更，经白名单校验后由内核执行 |
| 内核 | 持有全部事实的确定性代码层 |
| 关系轴 axis | 亲密 / 信任 / 张力 / 熟悉度等可独立移动的数值，默认对玩家隐藏 |
| 阶段 stage | 由轴推导出的关系标签，进 prompt 的是它而非数字 |
| 心结 knot | 未处理则持续存在的负面 flag |
| 晨报 morning update | 每游戏日一次的合并调用，给玩家当天的方向 |
| 钩子 hook | lead 类报纸条目，指向具体地点与时段 |
| 导演 director | 按（地点，天，时段）排程事件的调度器 |
| 正式 / 半正式 / 背景 | NPC 三层分级，决定调用方式与记忆深度 |
| 残影 | 地图上"三天前在这见过他"的动线痕迹 |
