# 本地完成通知

Tokimeki 的通知是用户显式开启的“生成完成提醒”，不是远程推送、后台生成或定时唤醒。

## 当前行为

- 入口：`设置 → 数据与隐私 → 本地完成通知`。
- 只有用户点击“启用完成通知”时才请求浏览器通知权限并注册最小通知 Worker。
- 面对面回复或终端角色回复完成时，如果页面仍在后台并且浏览器继续执行了完成回调，则显示一条通用通知。
- 页面在前台时不通知。
- 通知固定显示“回复已经生成，返回应用查看”，不包含角色名、台词、prompt、世界名或 API 信息，避免锁屏泄露内容。
- 点击通知时优先聚焦已打开的 Tokimeki 页面；没有页面时尝试打开应用作用域。
- 用户可以发送一条显式测试通知，也可以随时关闭完成通知。

## Service Worker 边界

`public/notification-sw.js` 只监听 `notificationclick`，不包含：

- `fetch`
- `push`
- `sync` / `periodicsync`
- Provider 请求或鉴权
- Cache Storage
- IndexedDB 读写

关闭通知后不再调用展示函数。Worker 可以保持注册但处于空闲状态；保留注册避免误删未来可能与同一作用域共享的离线壳能力。它不能读取 API key，也不会使 Provider 请求在后台继续。

## 平台限制

- 通知要求 HTTPS 安全上下文；本地开发的浏览器例外由浏览器决定。
- Android 浏览器/PWA 的通知展示由浏览器、系统通知权限和省电策略共同决定。
- iOS/iPadOS 的 Web 通知支持依赖系统版本、WebKit 和主屏幕安装形态；普通 Safari 标签页不能作为通用支持目标。
- 用户拒绝权限后，网页通常不能再次弹出授权框，需要用户到浏览器或系统设置中修改。
- 如果系统在回复完成前冻结页面，完成回调不会执行，因此不会产生通知；返回前台后继续使用既有中断恢复流程。
- 本功能不会在应用关闭后提醒夜间来信，也不会按游戏日或现实时间唤醒应用。

## 网络与隐私

启用、关闭、测试和显示通知都不调用 Provider。Service Worker 脚本是应用自身的静态文件；没有推送订阅端点，不向第三方发送设备标识或订阅信息。

## 真机验收

用户在 Android 浏览器/PWA、iOS Safari/主屏幕 PWA 分别检查：

1. 未点击启用前不出现权限请求。
2. 允许权限后测试通知可见，点击后能返回应用。
3. 页面前台完成回复时不显示通知。
4. 页面后台但尚未被冻结时完成回复，可显示通用通知。
5. 拒绝权限后显示可读提示，不反复请求。
6. 关闭开关后不再显示完成通知。

测试结果应记录设备、系统和浏览器版本。某台设备成功不能推广为所有 Android/iOS 环境都支持。
