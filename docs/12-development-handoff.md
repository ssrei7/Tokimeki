## 1. 新窗口最短启动流程

1. 完整阅读根目录 `AGENTS.md`。
2. 完整阅读本文。
3. 根据当前任务，只阅读本文列出的相关文档章节，不必默认通读所有历史决策。
4. 执行 `git status --short`、`git log -5 --oneline`，确认没有覆盖用户修改。
5. 核对 `src/data/schema/save.ts` 中的 `CURRENT_SCHEMA_VERSION`。
6. 每次只开始一个垂直切片；先报告范围、数据边界、API 调用和是否需要 schema migration。

推荐的新窗口开场指令：

```text
请在 D:\CodexProjects\tokimeki 继续开发。先完整阅读根目录 AGENTS.md 和 docs/12-development-handoff.md，再检查 git status、最近提交和当前 SaveFile schema。只按交接文档的链接补读与本次任务直接相关的章节，不必重新通读全部历史文档。保留所有现有修改和用户资源。一次只做一个垂直切片，完成后运行 build、全量测试、git diff --check，创建单独本地 commit，不 push，然后停止并报告剩余顺序。
```

## 4. 不可破坏的数据与安全边界

- AI 只能生成叙述文字和 ops 提议；时间、位置、数值、flags、库存、关系、事件等事实由确定性内核持有。
- 新玩法只能通过注册 op、事件钩子、prompt block 或数据包扩展，不得为单个功能改写核心循环。
- `core/` 不依赖 DOM、IndexedDB、React、Provider 或网络。
- 持久化位于 `data/`；Provider 请求实现位于 `providers/`。
- 默认零 API。只有用户显式点击生成、重生成、连接测试或其他明确联网操作时，才允许单次调用。
- API key、鉴权 headers 和用户数据不得发送到非用户显式配置的端点。
- 二进制只进入 Assets IndexedDB；SaveFile、聊天、包 JSON 只保存 `AssetRef`，禁止写入 base64。
- 外链图片只保存合法 `http(s)` URL，不自动下载；作为锁脸参考时，只有本地二进制才能进入 multipart edits。
- API key 不进入世界包、角色包、事件包、主题包或普通全局备份。
- 新界面必须优先使用语义化 CSS 变量和公共组件，不新增零散硬编码视觉样式。

## 5. 用户创意工坊的下一步方向

创意工坊是阶段 10 收尾后的推荐首要方向。目标是让用户调用自己配置的 AI，生成可预览、可安装、可编辑和可分享的终端 App / 玩法包。

首要安全结论：不允许 AI 生成并直接执行 JavaScript、TypeScript、React、HTML、任意 CSS 或任意网络请求。AI 只能生成声明式 App 草案，由本地 schema 校验器和受限运行时解释。

推荐包结构：

```text
manifest.json       包 ID、名称、作者、版本、兼容版本和权限
app.json            页面、受限组件、导航、表单和按钮动作
rules.json          声明式条件、活动规则、奖励表和冷却
events.json         可选 EventDef
prompts.json        可选、受预算限制的 prompt block
asset-meta.json     可选资产元数据
assets/*            可选本地二进制资产
```

受限 UI 首版只考虑标题、正文、图片、卡片、列表、标签页、按钮、输入框、选择器、进度和确认框。动作必须来自白名单，例如本地导航、App 草稿状态、读取经授权的世界事实、提交已注册 op、触发已安装事件，以及用户显式触发 Provider。

AI 制作流程应为：

1. 用户填写自然语言需求。
2. 用户显式点击生成，最多调用一次已配置文本 Provider。
3. AI 返回结构化草案，不直接安装、不写世界状态。
4. 本地完成 schema、引用、权限和兼容性校验。
5. 显示 App 预览、权限清单、冲突和不支持能力。
6. 用户确认后安装，终端桌面才出现图标。
7. 导出分享包时排除 API key、Provider 配置、用户存档和游玩状态。

真正的钓鱼、种田、开店结果必须由确定性活动引擎计算；AI 只描述已经确认的结果。某项需求若没有已注册通用动作，工坊必须显示“不支持”，不能退化为任意代码或让 AI 直接改状态。

### 推荐垂直切片

1. **已完成**：定义 App 包 schema、权限枚举、校验报告、导入导出和本地安装/卸载；不接 AI，不渲染动态 UI。
2. **已完成**：实现受限 UI 渲染器、终端动态图标和只读/本地状态组件。
3. **已完成**：实现工坊编辑器、实时预览、权限与冲突展示。
4. 下一步：接入用户显式触发的 AI 草案生成；结果必须先校验和预览。
5. 注册通用确定性活动 op / 钩子，使玩法包能够配置钓鱼、种田、开店等规则。
6. 完成包更新、版本依赖、卸载保护、全局备份和完整性审计。
7. 用“热点 / 活动 App”制作首个官方示例，验证分享工作流。

创意工坊原始想法见 `docs/ideas.md` 的“用户创意工坊 / 玩法包”。正式编码前应先形成独立计划并确认包状态放置、权限模型、跨世界绑定和卸载语义。

## 7. 验证与提交纪律

每个垂直切片完成后必须运行：

```text
npm run build
npm test -- --run
git diff --check
```

每个切片创建一个本地 commit，不 push；提交后停止并报告剩余工作顺序。界面实际手测由用户负责，代码侧只做短时 smoke、自动测试和边界验证。真实 Provider、Android/iOS、PWA standalone 与 Media Session 真机能力不能由桌面自动测试替代。
